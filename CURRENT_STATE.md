## Not proven yet

- **No KNC compiler code exists yet.** Only stock x86_64 GCC 16.2 has been built. Milestone M0 is the first KNC result.
- **The 5-minute T1 loop is marginal on Cygwin.** An `i386.md` rebuild took 265 s of the 300 s budget, with nothing else measured in the loop. S0-06 recommends comparing WSL2 before M0. Peak memory was not measured.
- **Nothing has run on the card.** Card minutes so far: 0. `tools/card_run` is merged but has only run against a fake card. S0-04 is done with its native line unticked: the `hello` and `m1_affine` runs wait for the owner's card hold to end. Before the first run the owner fills in `config/card.local.json` (host, identity, knownHosts). The first run on an idle card will refuse and list the card's user-space processes, which the owner then approves as `baselineNames`. The card-side tools the runner checks for (`readlink`, `stat`, `base64`, and others) are not confirmed on the card's BusyBox; if one is missing, the runner refuses rather than runs.- **The donor inventory's port, rewrite and drop table** was read by the Claude review, which found no error, but nobody has checked it against all 85 changed paths. The lead spot-checked the LRA lines and five runtime citations, all correct.
- **The `0002` reproducer is compile-only and not wired in.** It shows the dropped setup in the RTL dump; no wrong result has been run on the card, nothing about it has been shown on GCC 16 (where the guard above blocks the path unmodified), and no test runs it. E2-02 wires it in.
- **The corpus coverage numbers are a host proxy only.** S0-07 compiled with GCC 14.4 for AVX-512, nothing was run, and loop counts are not time. NPB FT, one HPCG file and three zlib gzip files did not compile and are left out. Runtime share waits for card profiles in S6.
- **GCC 16's `k1om` output is not KNC code yet.** At `-O2` it emits `cmovge`, which `as --march=k1om` and the lint both reject, and it predefines `__SSE__`, `__SSE2__` and `__MMX__` (lead, 2026-11-02). Expected until S1-04 adds `-march=knc`.
- Build files are owned by the sandbox user with Cygwin ACLs, so GCC builds must run inside engineer sessions. Polling a build cost one S1-02 session 15.5M input tokens; a single blocking call cost 1.4M and 3.5M. Ticket instructions for build steps should say "one blocking call".
- **Fast mode is not visible in session logs.** The dispatcher passes `service_tier="priority"` and high effort, but `codex exec --json` logs do not record the model or tier, so it is shown only by the command line.
- **The startup files from S0-03** come from the bootstrap sysroot. Only a run on the card will prove they suit the card's libc.

## Open items not on a ticket

Files with inherited permissions are fine, so create shared files outside the sandbox with native tools such as Git for Windows. `.work/_shared/check/donor` is stale and unused. `Copy-Item` from PhiWeather keeps those Cygwin permissions too, which locked the sandbox out of the 4 files the lead seeded for S0-10; `icacls <file> /reset` restored inheritance.
