Two findings recorded at M1 (`CURRENT_STATE.md`):

1. S3-22 routes the KNC varargs save through `mov<V4SF>`. The expander's assert
   (`i386-knc.cc`, near line 151) accepts `MEM_P (op0) && SSE_REG_P (op1)` but not the
   alignment. A store below 128-bit alignment would emit a mask-3 `vpackstorelq` that can split
   at a 64-byte line. Add `MEM_ALIGN (operands[0]) >= 128` to the assert. The only caller sets 128
   today, so generated code must not change. Also add `TARGET_64BIT` to the V4SF term in
   `ix86_knc_vector_move_mode_p`, if `-m32` with `-march=knc` is accepted at all (say which).
2. `tools/prepare_s3_10.py` writes the S3-15 ABI rows' expected files with the host libc's `%La`
   spelling (`0x1.c00000000000001p+0`), but card glibc prints `0xe.000000000000008p-3` for the
   same value. So `tools/run_s3_10.py` reports FAIL on equal values. Generate those expected
   lines in the card's spelling (x87 80-bit: a leading hex digit with the explicit integer bit),
   or compare the values instead of the text. Say which you did.
