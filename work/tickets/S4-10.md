Each GCC rebuild costs the laptop about 25 minutes when generated files must be regenerated.
`pm.py approve` causes one after every ticket that touches an `.md` file or `i386-knc.h`. It runs
`git checkout -q knc` in the shared GCC checkout (`tools/pm.py:476`) and then
`git merge --no-ff` of the ticket branch, so git rewrites every file that differs between `knc`
and the branch. Their times move past the build's generated files, and the next `make`
regenerates `insn-*` and recompiles most of `cc1`, although the content equals what was just
built. Seen on S4-09 (2026-11-04): `imci.md` rewritten at 12:03, after the 11:50 build.

Fix: build the merge without touching the work tree. When `knc` is an ancestor of the branch (the
normal case), the merge tree is the branch's tree. Create the merge commit with
`git commit-tree <branch>^{tree} -p knc -p <branch> -m <message>`, move `refs/heads/knc` to it
with `git update-ref` (old value checked), then `git checkout -q knc`. That checkout touches no
file because the trees are equal. If `knc` is not an ancestor, keep today's path. Keep the
existing refusal and rollback rules (`tools/pm.py:466-490`), and the main repo's merge as it is.

- [ ] After: the time is unchanged, `knc` has a two-parent merge commit with the branch's tree, the
