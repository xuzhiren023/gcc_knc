Sprint 12 improvement theme 2 of 3 (docs/research/m4-baseline.md, priority 2). Qualified exposure: the NPB-CG indexed
reduction, 24.5 s. HPCG's sparse kernels (GCC-KNC 1.8% slower than GCC 5.1.1, S11-28) have the same code property and
are a second, uncredited target.

Phase 1, proof (stop if the premise fails). On the CG sparse matrix-vector reduction and HPCG's SpMV/SymGS inner loops,
compare GCC-KNC and GCC 5.1.1 code at -O2: load scheduling of the index and value streams, address arithmetic,
spills in the loop, prefetch choice (S11-06/S11-09 findings), and whether vectorization (gathers) was taken and at
what cost. Keep the index order and FP accumulation order fixed. Stage one paired diagnostic batch (at most 20 min of
card time): host-built reproducers with cache-resident and memory-resident inputs plus a contiguous-loop control.
Write docs/research/s12-07-sparse.md: the removable cost and why.

Phase 2, only if phase 1 finds a removable cost: a general change (scheduling, cost model, prefetch or gather
profitability, addressing) keyed on code properties. Do not infer gather or prefetch profitability from load-PC
concentration alone; measure it. Strict FP order kept.

Acceptance:
- Red-then-green T1 test(s) on the intended generated code.
- T0-T2, x86 identity (ADR-0006) and the ICE sweep inputs pass.
- Stage for the lead a paired before/after GCC-KNC A/B on NPB-CG and HPCG (S11-28 fixed work) plus two controls
  (PB-gemm and zlib), serial -O2, full/3100/5100, through tools/corpus with checks on. HPCG reaching parity with
  GCC 5.1.1 is a goal, not a requirement.
- No held-out program is built, read or run.
