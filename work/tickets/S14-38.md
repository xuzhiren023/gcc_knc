Data sources (read-only; the dashboard never writes the ledger, never runs card_run, never opens SSH to the card):
- Card ledger: path from `config/card.local.json` key `ledger`, fallback
  `C:/Users/xuzhi/Documents/card-coordination/jobs.jsonl`. JSON lines; skip unparsable lines. Rows have `event`
  start/finish/queued/superseded and owner-cancel-request variants, `jobId`, `agent`, `project`, `purpose`,
  `startTime`, `expectedEnd`, `endTime`, `queuedTime`, optional `firstQueuedTime`, `cores`.
  Running: a `start` row with no later `finish` for the same jobId. Remaining = expectedEnd - now (negative shows as
  "overdue by ..."). Queue: a `queued` row with no later start/finish/superseded/cancel for that jobId, ordered by
  firstQueuedTime else queuedTime, as `tools/card_run` `own_turn` orders them. Rows whose jobId starts with
  `claude-turn-` and have `cores == []` are turn markers (whose turn it is), shown as such, not as jobs.
  Ignore stale rows the same way card_run's liveness check does (read tools/card_run near `active_jobs`; reuse its
  age limit rather than inventing one).
  Duration estimate for a queued job: median of finished durations (endTime - startTime) of earlier jobs with the
  same `purpose`, else the same `project` and `agent`, else unknown; say which basis was used. Estimated start of each
  queued job = running job's end plus the estimates before it; once one is unknown, later starts are unknown.
- Card temperature and utilization: `C:/Program Files/Intel/MPSS/bin/MicSmc.exe -t -c` on the host (about 1 s). Its
  output looks like "mic0 (temp):" then "   Cpu Temp: ...... 72.00 C" lines, then "mic0 (cores):" with
  "   Device Utilization: User:  45.03%,   System:   3.74%,   Idle:  51.23%" and "      Core #1:   User: ..." lines.
  Parse every mic device present. Timeout 20 s; on failure the panel says unavailable with the error.
- Host CPU: overall utilization in percent from a Windows source that needs no extra package (for example
  `typeperf` or `Get-CimInstance Win32_Processor` LoadPercentage via powershell); one call per refresh.
- Twin work: (a) host processes whose command line runs `knc_twin.py` (any copy, including other projects such as
  knc-boinc), with subcommand, working folder, start time and elapsed; (b) board tickets in state `doing` on lanes
  starting `twin-` (use tools/pm.py's board reading, not a second parser), with ticket id, title and session start
  if known. Remaining time for (a): median duration of earlier runs of the same subcommand that the dashboard itself
  saw finish, kept in `.work/_state/dashboard-twin-history.json` (the only file it writes); for (b):
  `session_timeout_minutes` from `harness/policy.json` minus elapsed, labeled as an upper bound. Unknown otherwise.

Refresh: collect at most once per 300 s server side (cache), so several open pages do not run MicSmc repeatedly; the
"refresh now" button forces one collection, rate-limited to once per 30 s.
