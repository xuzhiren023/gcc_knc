Twin lead 2026-11-16, defect found by knc-boinc S1-07 and confirmed by the lead in the code. `scripts/knc_model/
functional.py` `_x87_binop` (line 1914): fadd/fsub/fmul/fdiv are computed with `fp.F80` rounding and then, when the
precision control is 53 or 24 bits, re-rounded with `fp.convert` (lines 1925-1927). The comment "double rounding is
innocuous: 64 >= 2*53+2" is false: 2*53+2 = 108 > 64 (and 2*24+2 = 50 <= 64 holds only for the operations where the
exact result fits, not for division). Real x87 under PC=53 rounds the exact result once to 53 bits.
Repro (knc-boinc, `C:/Users/xuzhi/Documents/knc-boinc/twin/x87-rounding-repro.json`, load, fmul, store, ret with an
independent native expected value): fmul 0xbf3982440b271580 x 0x3fc697fb0ebad540, control word 0x027f: twin
0xbf1202b59a43239e, native x87 0x...9f; the exact product is 48721223/2^106 below the midpoint, so ...9f is right. Effect
seen: six mismatching bodies of their gravity kernel at core scale, first differences at fmul/fmulp/fsubp, one grows to
8 ULP; their x87 host oracle and an x87 host build match the SSE reference, so the twin is the one that is wrong.

Fix: compute each binary operation once in the precision-control format (`fp.fadd/fsub/fmul/fdiv(a, b, fmt, pol)` with
fmt = F64 or F32 significand but the extended exponent range, as the x87 does: PC limits the significand only; overflow
and underflow thresholds stay those of F80), then widen the result to F80 bits exactly. Audit the same two-step path in
fsqrt, the memory-operand forms (`fadds/faddl` etc., `fiadd*`), `fprem`/`frndint`/`fscale` if present, and the
constant loads. Red first (one new test file): the knc-boinc repro as a functional test with the native expected value;
a case for each of add, sub, mul, div and sqrt where double rounding differs from single rounding at PC=53 (construct
them: results exactly at a 53-bit midpoint after 64-bit rounding), and the same at PC=24. Then selftest and the
held-out replay (`validate_heldout.py --cases --max-seconds 0`): timing predictions must not change unless a trace
depends on an x87 value (list any changed row with the reason before re-recording). `references/validation.md` records
the fix; `CAPABILITY_REPORT.md` section on x87 exactness updated. Host: no builds, no card.
