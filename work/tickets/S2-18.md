The card is mostly idle and this laptop cannot run KNC programs at all, so the card is where wrong
code shows (owner, 2026-11-03: use the card where it brings a net benefit). `tools/claude-torture.c`
(S2-08) runs its list one program at a time, which uses one of the 30 cores `claude-pin` gives
the job. The full `gcc.c-torture/execute` suite in the fork is 1,692 programs; run serially at the
current pace, that is many card minutes per batch.

- `claude-torture -j N LIST` runs up to N programs at once (default 1, keeping today's behaviour),
  each with the existing per-program time limit, and prints the same `PASS`/`FAIL`/`TIMEOUT name`
  lines, sorted by list order, so outputs compare across runs.
- Every child stays inside the job's pinned CPUs and its own `RLIMIT_AS`, as now. The job's
  declared `memoryMB` must cover N times the per-program limit, so the ledger's memory figure stays
  true; refuse an N that would not fit, before starting.
- A child that is still running at the job's time limit is killed with the rest of the job, as
  now; no orphan outlives the driver.
