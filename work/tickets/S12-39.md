2026-11-14/15: six tickets (S12-21, S12-30, S12-36, S12-37 and others) were blocked at submit because `pm.py submit`
requires the branch to contain main's (or knc's) head, and the Codex sandbox cannot run `git rebase`/`git merge`
in its worktree (`could not create .git/worktrees/<id>/rebase-merge: Permission denied`); each time the lead rebased by
hand, costing an engineer session and a lead round trip. Most of the time main had moved only by `pm:` status commits.

Deliver: (1) `submit` no longer refuses when the branch is behind main only by commits that touch nothing but
`work/`, `STATUS.md` and `CURRENT_STATE.md` (pm/status commits); approve's merge handles those. (2) When main has real
changes the branch lacks, submit still refuses, but the message tells the engineer to ask the lead to merge (not to
rebase), and `pm.py approve` gains an automatic `git merge main` into the ticket branch (main repo) and `git merge knc`
(GCC repo, gcc tickets) before its own merge, aborting cleanly and refusing with the conflicting paths on conflict
(coordinate with S12-03, which covers the abort). Host tests with temporary repos: behind-by-status-only submits;
behind-by-real-change refuses with the new message; approve auto-merges a clean case and refuses a conflicting one
without leaving a half-merge.
