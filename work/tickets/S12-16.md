Owner, 2026-11-14, following S12-11: "assume the basics are right (slot, memory population, power, cooling, a working
MPSS). How do we tune the whole system? How did HPC centres tune it? What is the best practice after reviewing all
these references?" S12-11 (`docs/research/host-phi-workstation.md`) covered setup, not tuning; build on it and on
`docs/research/knc-reference-gaps.md`, reusing `.work/_shared/host-phi-refs/` and `.work/_shared/knc-refs/` before
searching again. Do broad, deep live web research; save new documents to `.work/_shared/host-phi-refs/` (under 2 GB
total for this ticket).

Answer, layer by layer, for a dual E5-2690 v3 host (Haswell-EP) with one KNC card, for two workloads: LLM inference
and scientific computing (WRF, HPCG/STREAM-class, dense and sparse linear algebra, MPI symmetric runs):
1. Host BIOS/firmware: power profile, Turbo, C-states/C1E, P-states, Hyper-Threading, snoop mode (Early Snoop, Home
   Snoop, Cluster-on-Die), NUMA, memory patrol scrub/refresh, PCIe settings (ASPM, max payload, link speed).
2. Host OS: kernel parameters, CPU governor, tuned profiles, irqbalance and IRQ affinity for the Phi, automatic NUMA
   balancing, THP vs explicit huge pages, isolcpus/nohz_full, swap, timers; what Stampede/TACC, Tianhe-2/NSCC,
   NERSC, LRZ, Jülich and others actually set on their Xeon + KNC nodes, with the source.
3. Card and MPSS: card power management (PC3/PC6, turbo on the models that have it), ECC, card kernel command line,
   card-side THP and memory, micctrl/MPSS configuration, card OS housekeeping (cores reserved for the OS, daemons),
   clock source, and how centres configured the card OS for native and symmetric jobs.
4. Transfers and MPI: SCIF/DMA settings, registered buffers, CCL-proxy / OFED / Intel MPI fabric settings for
   host-card MPI, symmetric-mode rank and thread placement, host and card process pinning.
5. Runtimes and libraries: OpenMP affinity (KMP_AFFINITY / OMP_PLACES / OMP_PROC_BIND) on host and card, thread
   counts per core on KNC, MKL automatic offload and its thresholds, allocator settings, huge-page allocation.
6. Monitoring and validation: what to watch (micsmc, PCM/perf, temperatures, throttling) and the benchmark ladder
   centres used to accept a node (STREAM, DGEMM, HPL/HPCG, SCIF bandwidth, MPI ping-pong).

Deliver `docs/research/system-tuning-playbook.md`: first a step-by-step playbook in the order to apply it, each step
with what to set, why, the source (citation, page), how to verify it took effect, the expected effect with measured
numbers where a source has them, the risk, and how to roll back. Then the evidence per layer, marking each fact
verified, reported or inference, production vs pre-production hardware, and the MPSS/OS version it applied to.
Then a short section on what this means for our GCC-KNC card practice (`tools/card_run` defaults, profiles, thread
counts, page and allocator settings). Then contradictions between sources and which to believe. End with the
owner's measurement plan: the smallest set of before/after tests, in order, with time estimates.
