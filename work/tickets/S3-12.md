ADR-0006, rules 5 and 6. The owner wants the i386 path correct for x86 and portable to future GCC
releases, so both need a repeatable check. S3-11 uses this tool for M1.

`tools/portability.py`, two subcommands:

- `drill [--onto REF ...]`: for each REF (default `upstream/master` and the newest
  `upstream/releases/gcc-*`), run `git merge-tree --write-tree --merge-base=releases/gcc-16.2.0
  --name-only REF knc` in `.work/_shared/gcc`. Report the REF commit and date, the conflicting
  files, and for each conflict the hunk text, plus upstream's line churn since 16.2 in the files
  `knc` changes. Write a dated section to `docs/research/forward-port.md`. It changes no ref, index
  or worktree, and it never fetches.
- `x86 --tree A --tree B`: build a C-only `cc1` for `x86_64-pc-cygwin` from each tree (a commit
  or branch, checked out in its own worktree under `.work/_shared/`) into its own build directory
  outside `gcc-build`. Reuse an existing build directory incrementally. Then compile every torture
  compile file at `-O2` and at `-O2 -mavx512f` with both and diff the assembly. Report identical
  and different counts, and list each differing file. It refuses to start while any `make.exe`
  runs.

(1) tools/portability.py:163-176: the loop breaks on the first failure, so when tree A fails tree B never runs. A file that fails on both sides (expected for some torture files compiled by bare cc1) cannot be told apart from one that fails only on knc, and any failure at all makes the exit code 2. A failure on knc only is exactly the regression this check is for. Always run both compilers. Count 'both failed, same diagnostics' on its own, neutral for the exit code. Count a one-sided failure, or different diagnostics, as DIFFERENT, with both outputs printed. Keep exit 2 for tool errors only. (2) tools/portability.py:165: cc1 runs with only -quiet and the -O flags. The torture harness adds its own default options (see gcc/testsuite/lib/c-torture.exp, e.g. -w and the C-standard/permissive handling the newer GCC defaults need), so without them a large share of the corpus may fail on both sides and the check proves little. Pass the same default options c-torture.exp uses, and print them in the report. (3) tests/tools/test_portability.py:83-111: add one fake-cc1 case where only side b fails on one file and both fail on another. Assert that the first counts as different, the second as both-failed, and the exit code is 1.
