Twin lead 2026-11-16, from knc-boinc S5-01 (`C:/Users/xuzhi/Documents/knc-boinc/docs/twin-flags.md`, `twin/flags/`, read-only):
`prepare-native` returns invalid_input "memory blocks span 42944845376 bytes ... one contiguous image of at most 33554432 bytes"
for a kernel whose tree nodes and bodies sit at their real heap addresses. Any heap-pointer kernel (gravity, WRF with allocated
arrays, LLM decode buffers) is excluded from native measurement today, so the twin cannot be calibrated or checked on them.

Design first (one page in `references/native.md`), then implement:
- Segmented image: `init.memory` blocks grouped into segments (each at most the current cap, 4 KiB aligned); the generated
  program reserves each segment at its ORIGINAL virtual address with mmap(MAP_FIXED_NOREPLACE) (fall back to a clear
  error naming the segment if the address is taken), so pointers inside the data stay valid and no relocation of the data is
  needed; `knc_twin_mem+off(%rip)` relocation (S14-15) then applies only to code operands, and segments are filled from the
  request's files before the timed region.
- When the addresses cannot be mapped (kernel or loader regions), a relocating mode: every pointer-typed word the functional run
  observed being dereferenced is rewritten by a per-segment delta; the twin knows every address it read as a pointer (the trace),
  so the rewrite set is exact for the executed path and the request states that unexecuted paths are not covered.
- `request.json` records the segment table; `import-native` checks the measured program used the same table.
Red first (one new test file): a two-segment kernel 40 GB apart prepares into two segments with the right addresses and a
fixture program that assembles on the host (k1om toolchain in `.work/_shared/toolchain/cross`, no card). Then selftest and the
regress. Submit with the one-sentence note the owner reads. Host: no builds beyond assembling, no card.
