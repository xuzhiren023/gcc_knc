The owner's new host: HP Z840, two Xeon E5-2690 v3 (Haswell-EP, 12 cores each, AVX2/FMA, no AVX-512), DDR4-2133 ECC
RDIMMs, one Xeon Phi x100 coprocessor (our card; see docs/research/knc-characterization.md and config/ for what we
know about it), and an AMD RX 6700 XT (GPU research is a later ticket; here only its effect on slots, lanes, power,
cooling and BIOS settings).

Do broad, deep live web research and collect primary documents into `.work/_shared/host-phi-refs/` (never in git;
total under 2 GB). Cover, with sources:
1. Platform: Z840 slot map and which CPU socket owns each PCIe slot, lane widths, BIOS settings the coprocessor needs
   (above-4G decoding / MMIO size, PCIe link speed, power and C-states, NUMA), memory population for full bandwidth
   (channels per socket, ranks, 2133 vs 1866 with more DIMMs per channel), PSU and auxiliary power for the Phi plus
   the GPU, and cooling for a passive or active Phi in this chassis (HP and Intel guidance, owner reports).
2. Host OS and MPSS: which MPSS versions run on which Linux and Windows releases, kernel limits, and how others keep
   MPSS working on newer distributions; SCIF and host-card transfer tuning; NUMA placement of host threads and
   buffers on the socket that owns the Phi's slot.
3. Workload practice on host + Phi: native, offload and symmetric (MPI) modes; when the host's 24 AVX2 cores beat or
   help the card; LLM inference (weight streaming, quantization, memory-bandwidth bounds of DDR4-2133 vs the Phi's
   GDDR5, splitting layers or batches across host and card); scientific codes (WRF, HPCG/STREAM-class, dense and
   sparse linear algebra, MPI symmetric runs) with measured results from papers, labs and centres (TACC Stampede,
   PRACE, LRZ, Jülich, Colfax and similar).
4. Host compiler and runtime settings for Haswell-EP that matter for these workloads (flags, huge pages, NUMA
   binding, OpenMP placement), with measured evidence, not folklore.
