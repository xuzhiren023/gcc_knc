Follow-up from S2-11's review and the lead's first successful card run (2026-11-03, job
`claude-1cbd65df...`, `hello from KNC`, exit 0). Two gaps before longer card jobs (S2-10):

1. While a program runs, `tools/card_run:540-550` reads stdout and stderr with two new SSH
   connections per pass, about every 50 ms. A one-minute job would open some 2,400 connections to
   the card's `sshd`, which the other agent shares. Poll on the existing control session, or back
   off (for example 0.5 s rising to 5 s), so a job of N seconds opens O(N / 5) connections at most.
2. The result does not say which stale `claude-` dirs admission removed, so nobody can check that
   the dirs left by the earlier failed runs are gone. Add `reaped` (the removed paths) and
   `stale_kept` (paths kept because a live process uses them) to the result.
