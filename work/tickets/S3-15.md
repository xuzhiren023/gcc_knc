A lead review of S3-04, plus the PhiWeather project's lesson that matching symbols do not prove ABI
compatibility, found these gaps (2026-11-03).

1. **Packed vectors through varargs crash the compiler.** The lead reproduced it at `-O0` and `-O2
   -march=knc`, on the current build:
   ```c
   typedef float packed __attribute__((vector_size(64)));
   void g(int, ...);
   void f(packed *p) { g(1, *p); }   /* ICE: unrecognizable insn, extract_insn */
   ```
   The early exits for unnamed arguments at `i386.cc:3237-3240` (`function_arg_advance_64`),
   `3493-3512` (`function_arg_64`) and `5043-5050` (`ix86_gimplify_va_arg`) skip
   `classify_argument`, so the S3-04 guard never runs. A push of V16SF reaches `movv16sf` as a
   `pre_dec` store that `*knc_packed_move` cannot match. On the callee side, `va_arg(ap, packed)`
   compiles silently with an unratified layout. Both must give "unsupported KNC register ABI mode",
   as named arguments do (ADR-0005 point 6). That includes a struct whose only member is a packed
   vector.
2. **`ms_abi` skips the guard too** (`i386.cc:4497-4512`, `function_arg_ms_64`). Give the same
   error for packed arguments and returns under `ms_abi`.
3. **Complex values have no cross-check.** `_Complex float` currently travels as 8 bytes in lane
   0 of `zmm0` (and is returned with `vbroadcastsd`), and `_Complex double` in `zmm0` and `zmm1`.
   `_Complex long double` has not been looked at. None of these is tested against the donor.
4. **The rounding mode is untested across calls.** Nothing shows that an x87 control word or MXCSR
   set with `fesetround` survives a call into donor-built code and back, or the reverse.

Follow ADR-0006: in shared files, hooks only; the logic goes in `i386-knc.cc`. Allocation: 8 shared
lines. Stop and ask before passing it.

Acceptance:

- [ ] Red first: the varargs caller and callee, the single-member struct and the `ms_abi` cases
  give the error, not an ICE and not silence, at `-O0` and `-O2`
- [ ] The scalar ABI cross-check (`tests/abi` or wherever S2-02's lives) gains `_Complex float`,
  `double` and `long double` arguments and returns, both ways between donor and GCC 16, at `-O0`
  and `-O2`
- [ ] A rounding test: the caller sets each of the 4 modes with `fesetround`, calls a function
  built by the other compiler that does an inexact operation and returns `fegetround()`, then
  checks the mode and the rounded result. Both directions
- [ ] No regression: `tools/check t0 t1 t2 --compiler gcc16`, and the `-O2` torture compile sweep
- [ ] Native, in S3-10: the complex and rounding cross-checks print their expected values
