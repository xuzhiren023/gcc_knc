Each optional `tools/check.py` selection (`--scalar-abi`, `--atomics`, `--x87-spill`,
`--secondary-reload`, `--varargs-abi`) has its own `getattr` branch in the T1 and T2 paths. Twice
(S2-03, S2-06) a new flag read `self.args` directly and broke `tests/regress/test_check.py`, which
builds a `Runner` with `__new__`, costing a session found only at review. Sprint 3 adds vector
tests; make a new selection one table entry. No change to what any existing flag runs.

- [ ] Red first: a test that registers a new selection the way S3 tickets will, and runs it on a
  `Runner` built with `__new__` and no `args`, failing on the current code
- [ ] One helper reads every optional selection with a default, and the existing selections go
  through it, for T1 and T2
- [ ] A `--vector` selection exists, running `tests/t1/knc-vec-*.c` (none yet), for S3-04 to S3-09
