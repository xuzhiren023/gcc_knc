Wrong code from Sprint 3 (S3-06), found by the lead on 2026-11-04 with `tests/acceptance/s4_masks`
on the card (`claude-7a41e68c…`): `S4-MASKS FAULT sig=11 kernel=add_f32 n=16 o=1 where=0
addr=(nil)`. `addr=(nil)` is the general-protection fault S3-03 recorded for an aligned access on
a misaligned address.

Reduced (`-O2 -ftree-vectorize -march=knc`):
`void f (float *restrict c, const float *restrict a, const float *restrict b, int n)
{ for (int i = 0; i < n; i++) c[i] = a[i] + b[i]; }` emits
`vaddps (%rdx,%rax), %zmm0, %zmm0`, with `b + i` only 4-byte aligned. After `combine` both
loads are still separate `*knc_packed_unaligned_loadv16sf` insns (`A32`) and the add is
register-register. LRA then substitutes the load's memory into operand 2 of
`*knc_<knc_fp_binary><mode>3` (`imci.md`, near line 327). Its predicate `vector_operand` would
refuse that memory, but the constraint `"YJm"` accepts any memory. `sse.md` uses `Bm`
(`vector_memory_operand`) for exactly this.

Fix: use `"YJBm"` there. Audit every `imci.md` pattern with a packed-mode memory alternative
(`*knc_packed_move`, FMA forms, broadcasts, and anything added since) for the same gap, and fix
each one the same way, or say why it cannot be reached. No shared-file change.
