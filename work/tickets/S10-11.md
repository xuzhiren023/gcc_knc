Found by the lead's card qualification on 2026-11-11, compare set (65,536 blocks per function, S10-08 build
in `.work/_shared/S10-08/card/`, results in `.work/_shared/tmp/claude-next13-v1.log` and
`.work/_shared/S10-08/card/cmp-*.txt`). On the host (x86-64 build, MPFR-exact) all of these pass.

- **Double sin, cos, tan and atan2 exceed 1 ULP on the card** (MPFR-exact recheck of the dumped lanes):
  sin 1.395 (worst x=0x7f13000000000003), cos 1.446, tan 1.545 (worst x=0x5f54000000000002), atan2 1.236
  (worst x=0x41cfb07cd81b8f16, y=0xc1b536c582cd6336). sin/cos/tan's worst lanes are huge arguments, so the
  large-argument reduction is the first suspect. Their float forms, sinh/cosh/tanh and log10 pass.
- **cbrt and cbrtf crash on the card**: the compare jobs exit 139 (SIGSEGV), no summary line.

Find the cause on the host first: compile the members with the GCC-KNC prefix and compare against the x86 build
(likely suspects: FP contraction into FMA where the algorithm needs exact products or a separate rounding,
which the x86 build without FMA never does; x87 `long double` or an x87 fallback in a reduction step; a
by-value vector or stack alignment problem for cbrt). State the cause from evidence (assembly, a host
emulation of the card code path, or a minimal card reproducer for the lead to run), fix it in the library or
the compiler (whichever is wrong), and add a regression test for the cause.
