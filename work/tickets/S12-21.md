From the S12-14 audit (`docs/research/s12-14-model-audit.md` rows B02, B04, B05; K02). M4 scores serial programs (one
worker per core), but -march=knc schedules and sizes chains for density 4 by default (knc.md:70, i386.opt:1400,
i386-knc.cc:234), and prices scalar integer multiply at 3 cycles where R02 p.56 describes a ten-cycle path through
the FP unit (i386-knc.cc:164-169). Both may cost serial M4 time in every program (imul is common in address code).

Phase 1, proof (no GCC change): build the 14 development programs with the installed prefix at -O2 -march=knc twice,
default vs the existing density option set to 1, and record the code differences (instructions, imul count and
placement, chain counts). Stage one card diagnostic (S12-12 style, under 30 min, exclusive): a dependent and an
independent imul chain at one thread (32/64-bit, register and memory forms) to measure its latency, plus a paired
whole-program A/B of the two builds on four development programs that differ most (three pairs each, full profile).

Phase 2, only if phase 1 shows a gain or the imul latency is far from 3: either change the -march=knc default
density used for scheduling when no -mknc-density is given (and keep -mphinix/OpenMP builds at their own setting),
and/or correct the imul cost; red-then-green T1 tests on the intended scheduling or cost decision; T0-T2, x86 identity
(ADR-0006) and ICE sweeps pass; stage the paired A/B on affected programs plus two controls at full/3100/5100. No
held-out program is built, read or run.
