From docs/research/m4-bzip2-diagnosis.md: GCC 16 recomputes the compare in a merged return block so it cannot fold one load into each cmp; every byte step costs two extra instructions (about 34 of 66 cycles per iteration in mainGtU, GCC 5.1.1 does fold). Investigate on a synthetic byte-compare loop (not bzip2: held out): which pass merges the blocks (tail merging / cross-jumping / if-conversion), whether a KNC-safe target hook or cost avoids it without changing x86 output, model-first with knc-twin. Research ticket: may close with no change if the fix would touch shared code beyond ADR-0006 rules.
