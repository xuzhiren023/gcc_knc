Found by the lead in S5-18's suite build (2026-11-06). Before S5-16, a GCC generic vector of 32
bytes with 16-bit elements (`unsigned short __attribute__((vector_size (32)))`) had no supported
vector mode under KNC. It was BLKmode and passed in memory, and `gcc.c-torture/execute/pr109040.c`
compiled and passed on the card (S5-17 suite, 1,681/1,681). S5-16 made V16HI a supported transport
mode, so the type now has mode V16HI, and the KNC ABI hook rejects it: "unsupported KNC register
ABI mode" at `pr109040.c:8` (and the compile torture case `pr70240.c`).

The donor GCC 5 passes this argument on the stack. In its `foo (V m, unsigned short *ret)` at
`-O2`, `m` is read from `8(%rsp)` at entry, and GCC 5 notes that the ABI for 32-byte-aligned
parameters changed in GCC 4.6. ADR-0008 point 7 said "the ABI hook rejects the new modes"; that was
wrong for V16HI, because the type already had a working, donor-compatible ABI. The lead amends
ADR-0008 point 7 with this ticket.

Deliver:
- Under KNC, a V16HI-mode type is passed and returned exactly as the donor does: arguments on the
  stack with the donor's alignment and offset, results in memory through the hidden pointer.
  Classify it as memory in the KNC part of the argument and return hooks; do not reject it.
- V16QI keeps today's behavior. It was already rejected before S5-16, as part of backlog E6-07, so
  leave it alone.
- An ABI cross-link test in both directions against donor objects, in the existing T2 ABI style:
  a donor-compiled caller with a GCC 16 callee and the reverse. Cover a V16HI argument after six
  integer arguments, a V16HI argument mixed with float arguments, a V16HI return, and varargs if
  the donor allows it. It prints values only. The lead runs it on the card.
- `pr109040.c` and `pr70240.c` compile again. Report the KNC torture `-O0`/`-O2` before and after,
  with every changed function listed.
