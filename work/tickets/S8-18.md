Owner, 2026-11-08: close Sprint 8 faster with a second GCC checkout and build tree. Today every
GCC ticket shares `.work/_shared/gcc` and `.work/_shared/gcc-build`, so the gcc lane runs one
ticket at a time. pm.py already applies the WIP limit per lane (`next_action`), so a second lane,
`gcc2`, can run one more GCC ticket alongside the first if it builds in its own tree.

## What to build

- One resolver in `tools/storage.py`: `gcc_tree(root)` and `gcc_build_dir(root)`. With
  `KNC_GCC_SLOT` unset or `1` they return today's `.work/_shared/gcc` and `gcc-build`; with `2`
  they return `.work/_shared/gcc-2` and `gcc-build-2`. Everything else in `_shared` (toolchain,
  sysroot, corpus, staged binaries) stays shared.
- Live tools use the resolver instead of hard-coded paths: `check.py`, `gcc_build.py`,
  `knc_relocation.py`, `portability.py`, `toolchain.py`, `torture_compile.py`, `vect_suite.py`,
  `vect_ice_check.py`, `fast_math.py`, `libgcc.py`, `s8_02_checks.py` and any `s8_*` script on main.
  Finished sprints' scripts (`s5_*` to `s7_*`, `prepare_*`, `run_s3_10.py`) stay as they are.
- `dispatch.py`: a ticket with `lane: gcc2` gets `KNC_GCC_SLOT=2` in its session environment, and
  `git safe.directory` covers `gcc-2`. Lead review commands keep `git -C .work/_shared/gcc`
  (worktrees share refs, so `diff knc...<branch>` works for either lane).
- `pm.py`: `lane_of` accepts `gcc2`; both gcc lanes' tickets count as GCC tickets for every
  check that now keys on lane `gcc` (branch head, x86 report, changed-lines). Approval merges a
  branch into `knc` without checking out `knc` in either tree, as today's merge path does, or
  says which tree holds `knc`. `submit` on either lane refuses a branch that does not contain
  the current `knc` head; the engineer rebases first (two lanes now merge into one `knc`).
- `tools/gcc_build.py --slot 2` (or the env var) configures and builds `gcc-build-2` from
  `gcc-2` with the same options as slot 1.
- `AGENTS.md`: two short lines. A gcc2 ticket uses only slot 2 paths. Never touch the other tree.
  One build per tree at a time.

## Not in scope

Creating the `gcc-2` worktree and its first build. The lead does that after this merges
(`git -C .work/_shared/gcc worktree add ../gcc-2 knc`, then one build). Also out of scope:
moving tickets to the new lane.
