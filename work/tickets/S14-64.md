Lead 2026-11-17. Incident: S14-04's approval merged at 17:00:55 and then failed removing .work/S14-04 (Permission
denied), leaving an empty folder that was no longer a registered worktree. At 17:03:43 main was reset --hard to
s14/S14-04's head (fe068bd4), dropping five board commits; the lead recovered them by merge at 19b9c1d0. Any git
command run with cwd=.work/<ticket> when that folder is empty or not a worktree walks up to the main repository, so
approve's error path `reset --hard host_head` (cwd=worktree) and similar calls act on main.

Fix in tools/pm.py and tools/dispatch.py: every git call that targets a ticket worktree first checks that the folder
is a registered worktree of this repository on the ticket's branch (git -C <wt> rev-parse --show-toplevel equals the
worktree path, and git worktree list contains it); otherwise refuse cleanly and touch nothing. A ticket already in
state done is never approved or reset again. When worktree removal fails after a successful merge, record the ticket
as done anyway and report the leftover folder.

Red first in tests/tools/test_harness.py: an approval whose worktree folder exists but is empty refuses without
changing main's HEAD; an approval of a done ticket refuses; a failed worktree removal after merge still records done.
