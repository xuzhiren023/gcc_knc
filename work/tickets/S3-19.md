On 2026-11-03 a lead card job was refused with `unknown process identity in snapshot: b'sh: line
90: /proc/24267/status: No such file or directory'`. A process ended between the `/proc/[0-9]*`
glob and the read. The rerun passed.

Cause: `tools/card_run_remote.sh:54` and `:83` use `done < "$proc/status" 2>/dev/null`. The shell
applies redirections left to right, so a failed `<` is reported on the original stderr before
`2>/dev/null` takes effect. That stderr is part of the snapshot stream, so the error line reaches
the parser as an unknown record.

Fix: put `2>/dev/null` before the input redirect (`done 2>/dev/null < "$proc/status"`) at both
places, and check the rest of the remote script for any other `<` that comes before its `2>`.
In the Python parser, a line that starts with `sh:` must never be read as a process record. The
redirect fix is the real one; the parser can stay strict.
