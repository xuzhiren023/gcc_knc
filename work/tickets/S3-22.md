S3-11's audit (`docs/research/m1-result.md`, ADR form) found three KNC blocks left in shared files
after S3-13. M1 criterion 6 needs them gone, so M1 waits for this ticket.

1. `ix86_zero_call_used_regs` (`i386.cc`): an `error` and early return after
   `CLEAR_HARD_REG_SET`, in the middle of the function. Make it one entry hook,
   `if (TARGET_KNC) return ix86_knc_zero_call_used_regs (need_zeroed_hardregs);`, with the body
   in `i386-knc.cc`.
2. `ix86_target_macros` (`i386-c.cc`): calls `cpp_undef` for
   `__GCC_HAVE_SYNC_COMPARE_AND_SWAP_16` itself. Move the call into `i386-knc.cc` (the existing
   `ix86_knc_target_macros`, or a new helper behind one hook line). Check that the macro is still
   undefined after the move: the undef must still run after c-family defines it.
3. `setup_incoming_varargs_64` (`i386.cc`): `smode = TARGET_KNC ? TImode : V4SFmode` and an
   `if (TARGET_KNC) emit_insn (gen_knc_save_varargs ...) else emit_move_insn ...` in the middle of
   the save loop. The two `TARGET_SSE || TARGET_KNC` condition terms are allowed and stay. Reduce
   the rest to rule-1 forms without copying the loop into a KNC file (rule 3). One route: let the
   KNC move expander turn a store of a zmm register in the save mode into the same save, so the
   shared loop's `emit_move_insn` needs no branch. If no rule-1 form exists without a copy, stop and
   `ask` with the options and what each costs; do not pick one alone.

Then list every remaining hunk in the shared files
(`git diff releases/gcc-16.2.0 knc -- gcc/config/i386 gcc/common/config/i386`, KNC-only files
excluded) with its rule-1 form, in the ticket note. Any hunk that is none of the three forms is
either fixed here or named in the note with the reason.

No change in behaviour. The tests already exist: `tools/atomics.py` checks the CAS macro,
`tools/scalar_abi.py` the zero-call-used-regs diagnostic, and `tests/t1/knc-varargs.c` plus S3-15's
checks the varargs save. No new tests and no red step; the identical-assembly check is the test.
