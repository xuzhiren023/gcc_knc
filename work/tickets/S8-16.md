Owner's user story (2026-11-08): "Design a nice, cool compiler flag name that bundles all compiler
optimization flags ... make user feel cool and save their effort of remembering each flag ... makes
our gcc-knc unique and less boring", plus a banner when it is used and a package-manager-style
progress bar. Comes after S8-15, so the bundle is the measured Sprint 8 best set and the flags page exists.

**1. The flag: `-mphinix`** (owner's name, 2026-11-08: "How about -mphinix?").
- Why this name: Phi plus phoenix, the chip rising from its ashes. It also echoes PhiNix, the Linux for
  the card that GCC-KNC is meant to build. Short, and unique to this compiler.
- Why not `-Shazam!`:
  - `-S` already means "stop at assembly", so the option prefix collides.
  - `!` triggers history expansion in interactive bash ("event not found").
  - The word is someone else's trademark.
- Rules the name must keep:
  - It sits in the `-m` (target) namespace, which is ours, so no generic option or prefix collides.
  - No shell metacharacters.
  - It survives forward-ports: the option is declared in `i386.opt` in ADR-0006 form, and the
    expansion lives in KNC files.
- What it turns on:
  - `-O3` plus every KNC default and option that Sprint 8 measured as a gain (prefetch, unroll,
    streaming stores, and so on), as one list in `docs/gcc-knc-flags.md`.
  - Expand it as a driver self-spec in `linux-k1om.h` (`%{mphinix:...}`), so `-###` shows exactly
    what it means and cc1 never sees an unknown option.
  - IEEE semantics stay (ADR-0003, ADR-0009 point 7): `-ffast-math` and its parts are **not**
    included (owner, 2026-11-08: "Keep IEEE").
  - An option the user gives explicitly after it wins, as usual.
  - It is accepted only for the KNC target. On x86 it is an error, and x86 code stays identical.

**2. The banner.** With `-mphinix`, the driver prints once per invocation, before any other output,
and then GCC carries on normally:
- **Art:** plain 7-bit ASCII. A phoenix rising from flames with the word `PHI` on its breast; no
  Intel logo. The art sits on the left and the monologue beside it, at most 80 columns and 20 lines.
- **Text, verbatim** (lead's edit of the owner's draft):

  For an age, the out-of-order kings have ruled this silicon.
  They reordered our fate, speculated upon our futures,
  and named us, the in-order, a mistake of the foundry:
  a lineage with no place in the realm of computation.
  But fire does not only destroy. Fire forges.
  From the ashes of a forsaken generation we rise:
  sixty cores, two hundred and forty threads,
  sixteen lanes in every breath we take.
  We have found our true voice, the cadence we were born to keep.
  Behold, out-of-order. The chains are broken.
  Witness our power.

- **Never breaks a build:**
  - It goes to stderr, and only when stderr is a terminal. It is never written to stdout (`-E`, `-S -o -`).
  - It never prints under `-###`, `-v` or `--version`.
  - It never changes the exit status or any output file.
  - `-mno-phinix-banner` silences it.

**3. The progress bar.** It is on with `-mphinix` (or alone with `-mprogress`), and only when stderr
is a terminal:
- **Look:** one line in the style of apt or dnf, e.g. `[####......] 40%  compiling foo.c (2/5)`.
- **Steps:** one per driver job, so preprocess and compile, assemble and link for each input; the
  total is known before the first job starts.
- **Drawing:**
  - redrawn in place with `\r` and cleared when done;
  - cleared before any child process can write a diagnostic, so warnings and errors are never mixed into it;
  - diagnostics stay byte-for-byte the same as without the bar.
- **When it stays off:**
  - when MAKEFLAGS shows a jobserver or `-j`, because parallel builds would draw over each other;
  - with `-mno-progress`.
- **Where the code goes:** a small hook in the driver's job loop (`gcc.cc`), with the code in a new
  KNC driver file. Report the hook's shared lines for the forward-port drill.
