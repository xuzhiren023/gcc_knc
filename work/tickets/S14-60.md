Lead 2026-11-17. With ten lane dispatchers running, the gcc-lane dispatcher died at 10:38 EST with a traceback from
tools/pm.py board_lock (line ~71): os.remove(board.lock) raised PermissionError [WinError 32] because another process
had the file open. Other pm.py calls print "the board is busy" and refuse; the interactive lead's calls wait minutes.

Fix in tools/pm.py: treat PermissionError / sharing violations on the lock file like "busy" (bounded retry with
jitter, then a clean refusal), never an uncaught exception; a dispatcher that meets a busy board waits and retries its
next step instead of exiting. Keep the stale-lock rule unchanged. Red first in the existing pm tests: a lock file held
open by another handle makes board_lock retry and then refuse cleanly (no traceback). Host only. Submit with the
one-sentence note the owner reads.
