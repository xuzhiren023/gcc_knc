Twin lead 2026-11-16, from PhiWeather's 0.4.0 study (STUDY.md section 12.3 items 2 and 3; PhiWeather tree read-only).
1. `schedule` cannot take a block inside a function: `from_binary --loop` needs a backward branch, and a hand-sliced
   block keeps one adapter label per instruction, which the explorer rejects as "interior label". Add `from_binary
   --block ADDR..ADDR` (inclusive address range inside one function): drop labels no branch in the range targets, take
   x87 and register live-ins from a functional run of the whole function up to the block (or require `init.registers`
   and say which are missing), and emit a kernel the `schedule` command accepts. Red first on the S12-31 row-loop
   fixture (a block cut from it must schedule to the same best order as the loop form).
2. `batch` writes a full `prepare-native` request per candidate under `<out>/queue/` automatically, about 20 MB for a
   24,000-instruction kernel. Make that opt-in (`--queue`), keep the manifest's list of candidates that would go to the
   card, and say in summary.md how to produce the requests. Existing tests that read `queue/` pass `--queue`.
Selftest and regress; `SKILL.md` and `references/input-format.md` updated. Submit with the one-sentence note.
