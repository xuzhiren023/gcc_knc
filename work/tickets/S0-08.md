S0-01 copied the tools into `.work/_shared/toolchain`, and `tools/doctor` reports OK, but the
shared compiler still uses PhiWeather's folder. The lead confirmed this on 2026-11-01:
`k1om-mpss-linux-gcc -print-prog-name=as`, `-print-prog-name=ld` and `-print-sysroot` all
resolve under `PhiWeather/.tools/knc-bootstrap`, and so do its default include directories.
This closes the S0-01 criterion "nothing depends on the PhiWeather folder".

PhiWeather's folder stays read-only. Prefer a fix that needs no rebuild, such as a wrapper,
specs file or `-B` and `--sysroot` defaults. Ask if a rebuild looks necessary.

Acceptance:

- [ ] `-print-prog-name=as`, `-print-prog-name=ld` and `-print-sysroot` resolve inside the shared toolchain
- [ ] Compiling and linking a small C program with `-v -Wl,--trace` prints no PhiWeather path
- [ ] The sysroot used is the card-derived one, so programs still bind to the card's libc
- [ ] `tools/doctor` fails with a useful message if any of those resolves outside the shared toolchain, with a T0 test that proves it can fail

- 2026-11-01 21:35 lead note: Tested: `gcc -v` shows `--with-as`, `--with-ld` and `--with-sysroot` compiled in with PhiWeather paths, and `-B<shared>/cross/bin/` does not change `-print-prog-name=as` or `ld`, though the shared as and ld exist. Do not spend the session on -B. A wrapper can set --sysroot, but a no-rebuild fix may not meet the first acceptance line. If one quick specs attempt does not, stop and ask with what you tried; that is the rebuild question this ticket reserves.

- 2026-11-01 23:03 lead note: Also in scope, from the S0-03 review: nothing recreates the hand-made sysroot files (crt1.o, crti.o, crtn.o, libc.so and libc_nonshared.a in usr/lib64, plus the empty lib and usr/lib). Make the toolchain step that builds the sysroot recreate them, and have tools/doctor name that step when they are missing.
