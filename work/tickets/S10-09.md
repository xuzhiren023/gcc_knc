Owner's user story (2026-11-11): "add a user story in s10 to address the gap. We dont want keep it in
backlog. Get it done urgent." The gap (backlog E6-11, found by S10-08): under `-march=knc` there is no
V8DF division or square root. A double loop with `/` or `sqrt` stays scalar x87, and generic-vector code
(libknc_vmath's asin, acos, hypot) is lowered to 8 `fdivl` and an `fsqrt` loop. x87 FP64 division and
square root are also not correctly rounded on the card (double rounding, `knc-div-sqrt.md` 3.3).

As a user: a loop `c[i] = a[i] / b[i]` or `c[i] = sqrt(a[i])` on doubles vectorizes at `-O2 -march=knc`
(`sqrt` with `-fno-math-errno`), and every result is the correctly rounded IEEE value with IEEE specials,
as FP32 already is (S5-10, S5-11).

Design: `docs/research/knc-div-sqrt.md` section 3 (FP64 division and square root), section 1 (the
estimates; `vrcp23ps`/`vrsqrt23ps` measured on the card, `card-runs-s5.md`), section 2.4 (rare path for
specials, overflow and subnormal results), section 4 (entry points) and section 5 (proof and test
plan). The FP32 implementation is the model: `ix86_knc_expand_sqrt` and `ix86_knc_expand_div` in
`i386-knc.cc`, the `knc_sqrt_*`/div insns in `imci.md`, and `tests/regress/knc-sqrt-model.c`,
`knc-div-model.c`, `knc-div-sets.c`, `knc-sqrt-exhaustive.c`. Read section 3 and the FP32 code first.

Deliver:
- `sqrt<mode>2`, `div<mode>3` and `cond_div<mode>` for V8DF, extending the FP32 KNC entry dispatch
  (ADR-0006 forms; no new shared hunk if the existing KNC branch can take the mode). Dynamic rounding
  mode as FP32; `-frounding-math` behaviour as FP32.
- Square root: section 3.2 leaves one proof obligation (the final step when `d = m - g1^2` is
  inexact). Settle it on the host model before writing the expander: either show the bound holds, or
  use the variant 3.2 names (g1 computed so that d is exact, Markstein 2000 ch. 9, or one more
  refinement). Write the argument in the `i386-knc.cc` comment block beside the FP32 one.
- Division: section 3.1, including the all-ones significand blend and the rare path.
- Host models for FP64 (MPFR or 128/256-bit integer arithmetic) as committed host tests under
  `tests/regress/` with a Python runner: Markstein reciprocal class, near-midpoint hard cases (128-bit
  modular construction, section 5.2), all-ones divisors, exponent sweep with overflow and subnormal
  results, specials, four rounding modes. Keep runtime under 10 minutes.
- One native program for the lead, `tests/regress/knc-v8df-divsqrt.c`, that runs the compiled vector
  division and square root over those sets plus 2^28 random operands, checks each lane with the
  128-bit residual test (`s5_ops` `div_ok`/`sqrt_ok`), compares specials and flags bitwise, and prints
  counts only.
- KNC cost entries for V8DF div and sqrt from the instruction counts, so a loop vectorizes when the
  sequence beats x87 (section 4.3).
- libknc_vmath: rebuild `vmath_asin.c` and `vmath_cbrt.c` (hypot) and confirm in the assembly that
  their generic-vector `/` and `__builtin_sqrt` no longer use the x87; host qualification unchanged.
