Found in the lead's card turn, 2026-11-12 15:44Z (boot da3144f1), after S11-03. The S11-01 native run still
stops before any transfer: the host runner times out in `listener.accept()` (`.work/_shared/tmp/claude-next20/
s1101-part1.out`), and card_run ends as program-failure after 3.5 minutes. Cause (lead, read-only check):
Windows Firewall is on for every profile, the host's adapters are on the Public profile, and the Public rules
for `python.exe` block inbound TCP and UDP; `transfer-host.exe` has no rule at all. So no connection from the
card to a host listener can succeed: not the lease control channel and not the `tcp` method's receiver on the
host. Changing the firewall is a security setting and is not in scope; the tool must work without it.

Make the host the connecting side everywhere, as card_run already is (outbound SSH):
- Lease control: the card helper listens on an ephemeral port on its mic address (or 0.0.0.0) and prints
  one line with the port and the nonce on stdout; the host reads it from card_run's output stream (or a
  separate SSH session reads it), then connects. Keep the nonce binding and the exact-directory and CPU checks.
- `tcp` method: for both directions, the card listens and the host connects. Do not open any host listener.
- SCIF is not affected by the firewall (not IP); leave it as it is. `pipe`, `scp` and `tar` already use
  outbound SSH.
- Search the tool for any other host `bind`/`listen`/`accept` and remove it.
- If a listener on the card cannot be reached either (card-side firewall), the run must fail fast with a clear
  message, not after a long accept timeout.

Rebuild `transfer-card.mic` with the GCC-KNC prefix, lint, and restage `.work/_shared/S11-01/` (helper, script,
runner and host program). Keep the existing loopback test passing; extend it so the fake transport also
connects host-to-card only.
