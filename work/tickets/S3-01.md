Backlog E3-02 to E3-04, design input. `docs/adr/0005-knc-packed-vector-modes.md` (Proposed) says
how V16SF, V8DF, V16SI and V8DI become legal under `TARGET_KNC`; this ticket checks it against the
source before any code. No fork change, no build, no card. Read source only through git, never
the shared checkouts' working trees, which the gcc lane switches between branches:
`git -C .work/_shared/gcc show knc:<path>` for the fork, and
`git -C .work/_shared/gcc-donor show donor:<path>` for the donor. Cite line numbers from those.
You may assemble one-line probes with the shared `as --march=k1om` in a scratch folder. Intel 327364 is under `.work/_shared/` once the
owner places it; if it is missing, ask.

Deliverable: `docs/research/knc-packed-modes.md`, short, every claim with a `file:line` in the fork
or donor, an `as` result, or a 327364 section.

Acceptance:

- [ ] For each of the four modes, every standard name that vectorizing the `m1_affine` loops and
  V16SI add, sub, mul, and, or, xor needs, including `mov`, `movmisalign`, `vec_duplicate` and
  `vec_init`: where it is instantiated (`sse.md`, `mmx.md`, `i386.md`, or nowhere), its condition,
  its iterator entry, and what its body calls
- [ ] For each iterator ADR-0005 point 2 would widen: every pattern using it, and whether its whole
  condition becomes true under KNC with only that entry widened. Name each one that would
- [ ] Whether a second definition of an existing standard name in `imci.md` fails to build, shown
  from the generator source (`gencodes.cc`, `genemit.cc`, `genopinit.cc`), not by building
- [ ] Every hook the vectorizer, expansion or register allocation reaches for these modes that
  tests SSE or AVX-512, at least: `preferred_simd_mode`, `vector_mode_supported_p`,
  `hard_regno_mode_ok`, `modes_tieable_p`, `get_mask_mode`, the vectorization costs, misalignment
  support, `standard_sse_constant_p` and the move predicates, `classify_argument` and the
  function value path, the reload class hooks, and spill slot alignment. For each: what it does
  under KNC once the modes are legal, and the change needed
- [ ] ADR-0005 question 3: a register-only broadcast for V16SF and for V8DF that is correct per
  327364 (swizzle groups for 64-bit elements), or a statement that there is none
- [ ] Which cost model applies at `-O2`, `-O2 -ftree-vectorize` and `-O3`, and whether the
  `m1_affine` loops need peeling, versioning or `movmisalign` under each, given the driver's arrays
- [ ] Estimated shared-i386 lines for S3-04, S3-05, S3-06, S3-07 and S3-09, in the measure in
  `docs/sprints/SPRINT-03.md`, and which parts can go in `i386-knc.cc`. Name any ticket over its
  allocation
