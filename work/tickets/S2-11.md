The owner requires every card job to honour the shared lock on the card,
`/tmp/knc-phase3-workload.lock`, and to hold an exclusive card window while it runs (2026-11-03).
`tools/card_run` only `lstat`s `externalLocks` on the host (`tools/card_run:90-97`), so today it
would never see that lock. Add a card-side lock to the runner, configured as `remoteLock` in
`config/card.local.json` (and a placeholder in `config/card.example.json`).

Acceptance (T0 with the fake transport; no card access in this ticket):

- [ ] Red first: T0 cases fail before the change for: lock present on the card (refused, no
  staging, no exec); lock taken by another holder between the idle check and exec (refused); our
  lock released on success, nonzero exit, timeout and transport loss; a lock we did not take
  never removed
- [ ] Taking the lock is atomic on the card, in the same control session as the process checks,
  and before staging. The lock is held until our run dir is cleaned up, then released only if
  this invocation took it and the boot ID still matches
- [ ] The card-side watchdog also releases our lock if the control session dies, after the same
  grace it uses for our run dir
- [ ] `docs/card-run.md` describes the lock and its protocol in a short section
