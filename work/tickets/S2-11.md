**First, before the lock work:** the lead's first real run (2026-11-03, donor `hello`) connected
and verified the host key, then failed with `SSH transport failure: remote operation failed
(status 94)`. That is `check_tools` at `tools/card_run:176-177`: one of `readlink stat id cat
base64 chmod tail head sleep mkdir rm` is missing on the card, and the runner does not say which.
Make the refusal name every missing tool (red first in T0), run `tools/card_run` once on the
donor `hello` to learn the names, and replace each missing tool with one the card has, with a
fake-transport T0 case per replacement. Then a donor `hello` runs to exit 0 on the card. Use the
card only through `tools/card_run`; the owner reports it idle and approved runs on 2026-11-03.
Build `hello` with the donor as `tools/check.py` does.

The owner requires every card job to honour the shared lock on the card,
`/tmp/knc-phase3-workload.lock`, and to hold an exclusive card window while it runs (2026-11-03).
`tools/card_run` only `lstat`s `externalLocks` on the host (`tools/card_run:90-97`), so today it
would never see that lock. Add a card-side lock to the runner, configured as `remoteLock` in
`config/card.local.json` (and a placeholder in `config/card.example.json`).

Acceptance (T0 with the fake transport, plus the runs named above):

- [ ] Red first: T0 cases fail before the change for: lock present on the card (refused, no
  staging, no exec); lock taken by another holder between the idle check and exec (refused); our
  lock released on success, nonzero exit, timeout and transport loss; a lock we did not take
  never removed
- [ ] Taking the lock is atomic on the card, in the same control session as the process checks,
  and before staging. The lock is held until our run dir is cleaned up, then released only if
  this invocation took it and the boot ID still matches
- [ ] The card-side watchdog also releases our lock if the control session dies, after the same
  grace it uses for our run dir
- [ ] `docs/card-run.md` describes the lock and its protocol in a short section

- 2026-11-03 10:12 lead note: The owner has no preference on the protocol, so the runner must be safe under both. Take: create the file atomically only if it is absent (`set -C`), and refuse if it exists; then hold `flock -n` on it for the whole run, and if `flock` is missing on the card or fails, remove our file and refuse. Release: drop the `flock`, then remove the file only if this invocation created it and the boot ID matches. A lock file that stays on the card permanently therefore makes every run refuse: that fails closed, and the refusal message must say so. Set ready under the owner's 2026-11-03 delegation.
