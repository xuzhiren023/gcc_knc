Owner request 2026-11-16 (relayed by the knc-boinc session): the installed knc-optimize skill (S14-42,
`skills/knc-optimize/`) must detect whether GCC-KNC is available and pick its mode, and report the mode at the top of
every run.

- **Combined mode** (GCC-KNC present): terms a compiler can fix (vectorization, vector math calls, scheduling,
  prefetch, x87 scalar code, register allocation) go to GCC-KNC as a ticket request with a reduced repro plus
  `-fopt-info-vec-missed` output or knc-twin evidence, sent to the GCC-KNC lead; only what a compiler cannot do
  (algorithm, data layout, bit-exact ordering, exact-fallback logic) is hand-written in the application.
- **Hand mode** (GCC-KNC absent: stock MPSS gcc or icc on another machine): hand-optimize everything with
  intrinsics or source changes, and list which items a better compiler would have done.

Detection, in order; record which rule fired:
1. `GCC_KNC_ROOT` set: use `$GCC_KNC_ROOT/bin/k1om-mpss-linux-gcc`.
2. A `k1om-mpss-linux-gcc` on PATH or at a path the calling project names.
3. A driver is GCC-KNC only if it accepts `-march=knc -mveclibabi=knc` on an empty translation unit (`-x c -S -o
   /dev/null -`) and `-dumpversion` gives major 16 or later. `--version` prints plain "(GCC) 16.2.0", so it cannot be
   the test. Stock MPSS gcc 5.1.1 and icc fail rule 3 and give hand mode.
4. Nothing found: hand mode, and say how to point the skill at GCC-KNC.
On Windows/Cygwin hosts the driver may need its toolchain DLL folder on PATH (cygmpc-3.dll); the detection script
reports a driver that will not start as "found but not runnable", not as absent.
