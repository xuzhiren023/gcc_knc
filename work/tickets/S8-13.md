Backlog E5-08; ADR-0009 point 5 and amendment 1 point 1. S8-01's C1
(`docs/research/knc-characterization.md`): with the `lock addl` fence, `vmovnrngoaps` beats normal stores
3.1x at one thread, 1.6x at 4 threads on one core and 2.7x on the whole card (226 against 84 GB/s);
`vmovnraps` loses on one core and is never chosen. The amendment kept streaming stores off until a
60-core gain was shown; it now is.

Deliver: a `storent<mode>` pattern for V16SF/V8DF/V16SI/V8DI emitting `vmovnrngoap*`, used through
GCC's existing non-temporal store path (`tree-ssa-loop-prefetch.cc` marks stores it judges beyond the
cache; S8-03 turns loop prefetching on for KNC), legal only for an unmasked, unconverted store of a
whole 64-byte-aligned line in a loop that writes every line it touches; and the KNC fence the path
needs after the loop (`lock addl $0,(%rsp)` or the C1 drain; no `sfence`/`mfence` on KNC), placed
before any call, return or loop exit that could publish the data. L2-resident loops keep normal
stores (C1 measured memory-sized footprints only).

Acceptance:

- [ ] Red first: T1 scans that require `vmovnrngoaps` plus the fence for a large write-only copy or
  set loop, and normal stores for a masked, partial-line or L2-sized loop
- [ ] An execute test where one thread streams an array and another reads it after a flag: no stale
  data at 60x4 (the fence is placed before the flag)
- [ ] The lead's paired card run includes the M2 memory working set; the write-only case must be
  faster and no L1/L2 row slower
- [ ] The M2 kernels, `s4_masks` and `s5_ops` still pass on the card; the lead measures the M2
  kernels before and after with the S6-15 paired fixture (`build.py --before`, `decide.py`); no M2
  kernel slower beyond the 1.6% A/A bias, and claims under 3% get a link-order check (ADR-0010)
- [ ] T0/T1/T2 otherwise unchanged; torture changes listed; x86 assembly identical (`-O2` and
  `-O2 -mavx512f`); shared i386 lines and hunks reported (ADR-0006 forms only)
- [ ] No card job by the engineer; stage binaries under `.work/_shared/<ticket>/` for the lead

- 2026-11-09 06:26 lead changes: Red is close; four changes before green. (1) Fence placement is not tested: every fence scan matches a lock addl anywhere in the function, so a fence at entry passes. Require order in each NGO function: the last vmovnrngoap* comes before a lock addl, and that fence comes before the ret, with no NGO store between the fence and the ret. Add one T1 function where the NGO loop is followed in the same function by a flag store (or an extern call) and require the fence between the last NGO store and that store or call. This is the inlined publish case the ticket names. (2) Over-testing: drop the exact cmpq $4094/$2729 + jbe scans. The vmovaps-plus-vmovnrngoap* pair in stream_f32/f64 already proves the run-time versioning, and the guard's constant and instruction form are yours to choose (keep the threshold in the comment). Also drop the 'NGO loop must have vprefetch1' scan: that is S8-03's behaviour. Keep the no-output-prefetch scan, but make it robust to unrolling (for example no vprefetch0/1 whose address uses the store's base register), or drop it. (3) T2 strength: the reader checks y from index 0 upward, so by the time it reaches the last-streamed lines (the only ones likely still in flight) they have drained. Make the reader check the tail first (reverse order, or the last 64 KiB first and then the rest). (4) Add a --control mode to T2: a writer that streams with inline-asm vmovnrngoaps and no fence, so the lead's card run can show whether the card makes missing-fence staleness visible. Report it, don't gate on it. Keep the rest: the masked, converting, vpackstore and L2-resident negatives, the global no sfence/mfence/vmovnraps scan, and storent.py's NGO-path guard on stream_fill. Note for later, not this ticket: at -O2 a pure copy or set loop becomes memcpy/memset, so those never reach storent.
