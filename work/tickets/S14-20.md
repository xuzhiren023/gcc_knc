the gravity kernel's region contains `jmp *fprintf@GOTPCREL(%rip)` on a cold error path (a PLT tail call); the
twin refuses the region at parse time (`scripts/knc_model/asm.py`, the `*` operand branch raises `Unsupported`), so
nothing in the region can be checked although the path never executes.

Fix: parse an indirect `jmp *` / `call *` into an instruction of class `indirect_transfer` (new in `isa.py`) whose
functional handler raises `Unsupported` with the same message only when it executes; the timing engine never sees
it unless it executes. `capabilities` lists this ("indirect transfers are accepted when never executed"). The
functional result for a region that contains one but never reaches it is unchanged and exact; a region that does
reach it gets today's `unsupported` status, naming the instruction and address. S14-11's jump-table work (lane
twin-wrf) covers executed indirect jumps with a known table; do not duplicate it: coordinate through the ticket if
S14-11 has merged first (then the executed case goes through its table lookup, the never-executed case through this).

Red first in `knc-twin/tests/test_v03.py`: a kernel with a conditional branch around `jmp *sym@GOTPCREL(%rip)` that
is never taken runs to completion with the right result; the same kernel with the branch taken returns status
`unsupported` naming the jmp. Then selftest and regress (Windows python 3.8 or `--max-seconds 3600`, see S14-18).
