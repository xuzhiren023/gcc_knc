S11-29's sampler is correct but costs about 85% of one hardware thread (46-47k ticks in 550 s, USER_HZ 100), pinned to CPU 0, the OS core no profile job uses. Per sample it forks a shell to list /proc, iterates all ~1029 PIDs and forks sleep through system().

Deliver: a full /proc listing only every 10th sample (1 s) or when a known PID's child count changes. Read status for known descendants every 0.1 s. Replace the per-sample popen and system with a single long-lived helper if BusyBox allows. Measure in a lead card round: HPCG 3100@224 monitor ticks under 5% of one thread, and the 6 GiB toucher still classed as resource.

Found 2026-11-14 (S11-12 card turn): the monitor's `system("sleep 0.1")` (tools/card_run:146) fails on the card's BusyBox (`sleep: invalid number '0.1'`), 631 times in a 73 s bench run: the loop never sleeps and every profile run's stderr is flooded. Use a delay BusyBox accepts (`usleep 100000`, or `sleep 1` for the full-listing cadence); a host test that the generated script uses no fractional `sleep`. Fix this first; it may be most of the measured cost.
