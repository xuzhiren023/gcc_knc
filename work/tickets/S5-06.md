Backlog E4-06, part 1. Design: ADR-0008 point 1. The research, with the recipes, the risks and the
cheapest sequence for each selector kind, is `docs/research/knc-gather-reduce.md` sections 3 and 7
(ticket 1). Read both first.

Today `ix86_vectorize_vec_perm_const` returns false for all four 512-bit modes without AVX-512F
(`i386-expand.cc` near 25422), so reversed loops, stride-2 loads and even/odd extraction stay
scalar (`tests/acceptance/s5_ops` README, baseline).

Deliver:
- `ix86_knc_vectorize_vec_perm_const` in `i386-knc.cc`, reached by a first-statement
  `if (TARGET_KNC)` return (ADR-0006 rule 2, about 3 shared lines).
- The `imci.md` insns: `knc_permf32x4<mode>`, `knc_pshufd<mode>`, `knc_valignd<mode>`, a register
  swizzle move, and a write-masked `vpermd`.
- A classifier that tries identity, swizzle, `vpermf32x4`, `vpshufd`, `valignd`, one `vpermd`, and
  then `vpermd` plus a masked `vpermd`, so that every one-input and two-input constant selector
  is handled. `testing_p` must agree exactly with the expansion.
- For 8-lane modes, dword-pair `vpermd` indices.
- No swizzle on an insn with a rounding override.
- A KNC cost term for the two-`vpermd` form, next to S4-14's term in `i386.cc`.
- Add every new prototype in one `i386-knc.h` edit, before the first full build (`AGENTS.md`).
