Backlog E4-06, part 2. Design: ADR-0008 point 2. The research is
`docs/research/knc-gather-reduce.md` sections 4 and 7 (ticket 2). Read both first.

Today no `reduc_*` optab works for KNC. Integer sums use "reduce using scalar code", which keeps
the vector accumulator in a stack slot for the whole loop (research 2.3 and 4.2). S5-06 adds the
`vpermf32x4` and swizzle insns this ticket builds on.

Deliver:
- `reduc_plus_scal`, `reduc_smax_scal`, `reduc_smin_scal`, `reduc_umax_scal`, `reduc_umin_scal`,
  `reduc_and_scal`, `reduc_ior_scal` and `reduc_xor_scal` for the KNC modes each applies to:
  - plus for all four modes, V8DI through S4-04's carry sequence;
  - min/max for V16SI;
  - FP smax/smin only if S5-12 has landed, otherwise leave them for S5-12;
  - logic for V16SI and V8DI.
- Each is enabled through the `sse.md` expander with a KNC condition term and a first-statement
  entry dispatch to a tree builder in `i386-knc.cc` (ADR-0006 forms, about 20 shared lines).
- Swizzled-second-operand variants of add, min/max and logic in `imci.md`, used by the trees.
- No `fold_left_plus`. Without `-fassociative-math`, an FP sum stays GCC's in-order fold.

Acceptance:

  - the `int` sum is a `vpermf32x4` plus swizzled `vpaddd` tree, with no stack accumulator inside

  - `float`/`double` sums with `-ffast-math` emit the `vaddps`/`vaddpd` tree;
  - negative: `float` sums at `-O2 -ftree-vectorize` and at `-O3` without fast-math contain no
