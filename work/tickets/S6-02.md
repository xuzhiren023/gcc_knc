Backlog E5-06 and the M2 criterion (`docs/PROJECT_PLAN.md`). Method: S6-01's protocol (ADR-0010
once accepted). This is the M2 yardstick, so correctness of the references matters as much as
their speed.

Deliver `tests/acceptance/m2_kernels/` (lead-reviewed acceptance fixture):
- Kernels, each in its own function with `restrict` pointers and 64-byte aligned data:
  - FP32 affine `y[i] = a*x[i] + b` and FP64 affine (the `m1_affine` shapes);
  - a 1-D 3-point stencil and a 2-D 5-point stencil, FP32;
  - a short loop (lengths 1-64, variable) FP32 multiply-add;
  - a small fixed-shape matrix-vector product, FP32 (for example 8x8 and 16x16).
- Three builds of each: GCC-KNC `-O2 -ftree-vectorize -march=knc` (vector), the same with
  `-fno-tree-vectorize` (x87 scalar baseline), and a hand-written IMCI version in `.s` files
  assembled by binutils 2.22 (`--march=k1om`), with no intrinsics.
- A driver that checks every build against a scalar reference (bit-exact where IEEE allows; state
  any tolerance and why), then times each build per S6-01: lengths from 16 to beyond L2, L1, L2
  and memory working sets, and 1-4 threads per core. It prints one line per measurement:
  kernel, build, length, threads per core, cores, cycles per element, and repetitions.
- `README.md`: builds, the expected output format, and how the M2 numbers are derived.

  (`-DNEGATIVE_CONTROL`), then passes on the real one
