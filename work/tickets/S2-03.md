Backlog E2-01, varargs part. Varargs callers set `%al` to the number of vector registers used.
The callee saves those registers to the SysV register save area, 16 bytes per register from
`fp_offset` 48; the donor stores each with `vpackstorelq` under mask 3. `va_arg` of `double` must
read what a donor caller passed, and the reverse.

Acceptance (T1 and T2):

- [ ] Red first: a T1 test of `%al` at a varargs call and of the save-area stores, and a T2
  cross-link, fail before the change
- [ ] T1: `%al` set correctly for 0, 1 and 8 FP arguments, and above 8 (the stack overflow)
- [ ] T2: a GCC 16 `printf`-style varargs callee called from donor code, and a GCC 16 call to the
  card's libc `printf` and `snprintf` with `double` arguments, link against the card sysroot
- [ ] Native, once the card is free: `snprintf` of mixed `int`, `double` and `long double`
  matches the donor's output byte for byte
