Lead 2026-11-16. Owner priority is fast LLM decode on KNC. S14-08 (deep) will build and time four group-quantized
GEMV forms on the card. Before it does, rank them on one core with knc-twin 0.4.0
(`knc-twin/references/handoff-prompt.md` first, then `knc-twin/SKILL.md`). Follow `.claude/skills/model-first/SKILL.md`,
tier standard. KNC values come from `docs/research/knc-machine.yaml`. No GCC change, no card.

1. Write small self-contained C kernels for the inner tile of a 4-bit and an 8-bit group-quantized GEMV (group 32,
   K = 4096, 8 output rows per tile). Use the S14-08 forms: (a) FP dequantize; (b) multi-row with the activation
   preparation reused across rows; (c) int32 multiply-add (VPMADD231D, R27 with pages); (d) a VPERMD 16-entry lookup
   table. Use our own code only: PhiChat is read-only and not a source. Check each kernel against a double reference
   on the host (x86 build of the same C) before modelling it.
2. Compile at `-O2 -march=knc` (and `-O3` if it changes the inner loop) with the installed GCC-KNC. Per form and
   width: `from_binary.py`, `simulate` with weights resident in L1 and in L2, and `bounds --loop`. Record cycles per
   weight byte, the binding constraint, result_class and status as printed.
3. Convert to a per-core weight-bandwidth demand and compare it with the measured per-core memory service rate in
   `knc-machine.yaml`. Which forms are compute-bound on one core, and which reach the memory bound?

Write a ranked table and one paragraph in `docs/research/s14-28-gemv-forms.md`: which forms S14-08 should build and
time first, and which it can drop. Treat any difference under about 30% outside a validated shape as a tie for the
card. Kernels go under `tests/regress/s14_28/` so S14-08 can reuse them. Submit with the one-sentence note the owner
reads.
