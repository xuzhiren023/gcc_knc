Twin lead 2026-11-16, defect reported by the knc-boinc project on engine 0.4.0 (gravity kernel, 3040 dynamic
instructions, one context, profile card-7120-measured): `bounds` reports lower_bound_cycles 43,656 with binding term
dependency_critical_path while `simulate` predicts 33,622 cycles, both status ok. A lower bound above a valid execution
of the same model is a contradiction. Cause (read, not yet reproduced here): `scripts/knc_model/bounds.py` lines 48-61
give every first touch of a line its cold-level latency (latency.memory 328 or latency.l2_hit) on the critical path,
"capacity and prefetch timing ignored" (its own assumption text); the timing engine overlaps those misses through the
L2 hardware prefetcher (300 hw_prefetches in the reported run) and the memory service, so dependent loads on the path
wait far less than the full latency. The memory_concurrency term (5,658) is a true bound; the critical-path term is a
scenario, not a bound. Reproducer: C:/Users/xuzhi/Documents/knc-boinc/.work/S1-05/twin/kernel.json (regenerate with
`bash twin/run.sh` in that repo), with bounds/ and simulate/ result.json beside it; copy the kernel into
`knc-twin/fixtures/` as a regression input if its license allows (BOINC MilkyWay N-body is LGPL/GPL: use only our
compiled region record, which is the twin's own JSON, and say so).

Fix: the critical path's memory term in the lower bound must use the lowest latency any valid execution can show for
that access: the L1 latency when the line can be prefetched or already present, the L2 latency only where the model
proves it cannot be (no prefetcher, cold_level l2 in the scenario, or the line is the first in a stream the prefetcher
cannot have started). Report the cold-latency version separately as `dependency_critical_path_cold` (a labelled
scenario term, never the binding term of the bound). Add the invariant to the selftest: for every fixture kernel,
`bounds` lower_bound_cycles <= `simulate` predicted_cycles under the same profile and scenario (red first: the
knc-boinc region record must fail it before the fix). `references/bounds.md` says which terms are bounds and which
are scenarios. Selftest and regress; submit with the one-sentence note the owner reads.

  twin's own JSON region records into fixtures; WRF source stays out). `batch`'s "bound gap" 0.93-0.98 is the same defect.
