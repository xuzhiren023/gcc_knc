`gcc/config/i386/linux-k1om.h:50` (ported from the donor in S1-06) adds `crtfastmath.o` for
`-mdaz-ftz`, `-Ofast`, `-ffast-math` and `-funsafe-math-optimizations`, but S2-07's `libgcc`
builds no fast-math startup file (`libgcc/config.host:807-810`), so those links should now fail.
The donor's `crtfastmath.o` is `stmxcsr; orl $0x8040; ldmxcsr` (FTZ and DAZ), and the lead ran a
donor `-Ofast` hello on the card on 2026-11-03: it links that file, executes the `ldmxcsr`, and
exits 0. So setting FTZ and DAZ does not fault on KNC (SSE's exception-mask bits 7-12 do, per
`docs/research/phiweather-scan.md`). Whether FTZ and DAZ take effect on KNC is not shown.

Build a KNC `crtfastmath.o` from the fork that does what the donor's does, as mainstream GCC does
for `-ffast-math`: read MXCSR, set only bits 15 and 6, write it back. No CPUID test, and never
touch bits 7-12 or 20, or clear bit 21.
