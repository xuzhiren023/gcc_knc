Found by the lead's full execute-suite build after S3-07 merged (2026-11-03). It is the only ICE
among the suite's 1,692 sources at `-O2 -march=knc`, and it also happens at `-O0` and `-O1`:

```c
typedef char V __attribute__((vector_size (64)));
static void __attribute__ ((noipa)) foo (V *p) { V v = *p; v[63] = 1; *p = v; }
int main () { V v = (V) { }; foo (&v); /* ... */ }
```

```
error: unrecognizable insn:
(insn 6 2 7 2 (set (mem/c:XI (plus:DI (reg/f:DI 93 virtual-stack-vars) (const_int -64)))
        (mem/u/c:XI (symbol_ref/u:DI ("*.LC0")))) ... -1
during RTL pass: vregs  ... in extract_insn, at recog.cc:2892
```

`char` vectors are not a KNC vector mode, so a 64-byte `char` vector is XImode, the 64-byte
transport mode from Sprint 2. Its move expansion lets a memory-to-memory set through: here the
zero initializer comes from the constant pool. The stock `ix86_expand_move` forces one operand into
a register when both are MEMs; the KNC path apparently does not for XImode. This probably predates
Sprint 3: S2-08's 256-program subset never included this test.

Fix it in the KNC move path (ADR-0006: logic in `i386-knc.cc`, a hook only in shared files). A
memory-to-memory XImode copy goes through a register or by pieces, whichever is legal on KNC. Also
check `foo`'s element store `v[63] = 1` on XImode.
