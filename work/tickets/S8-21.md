S8-11's batch check (`docs/research/forward-port.md`, "S8-11 compiler-prefetch column case") found
that `-fprefetch-loop-arrays`, on by default for `-march=knc` (S8-03), emits **no** prefetch for a
WRF-shaped column loop with 8-float rows: the vectorizer makes each row a 16-lane `.MASK_LOAD` with an
8-lane mask, and `gather_memory_references` in `tree-ssa-loop-prefetch.cc` only collects
`GIMPLE_ASSIGN` references, so the loop has nothing to prefetch. With 16-float rows the same loop gets
58 `vprefetch`. Any row shorter than one vector (WRF's 8-float rows) is never prefetched.

Deliver:
- `gather_memory_references` also records the address of `IFN_MASK_LOAD` and `IFN_MASK_STORE` (and
  the `_LEN` forms if trivial) as a read or write reference of the vector's size, so the pass prefetches
  them like plain accesses.
- This is a middle-end change in a shared file: keep it minimal and generic (no KNC test in it), in
  one commit, and report its lines. x86 code at the identity flags (`-O2`, `-O2 -mavx512f`) must stay
  identical: those do not enable `-fprefetch-loop-arrays`.
- Rebuild S8-11's prefetch column case (`tests/bench/prefetch-column/`, 8-float rows): `column_pf` now
  has `vprefetch` and differs from `column_nopf`; stage it and an M2 pair against the knc head for the
  lead.
