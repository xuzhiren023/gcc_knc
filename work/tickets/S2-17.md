Three of the lead's card runs on 2026-11-03 failed with `unknown process identity in snapshot`
(`tools/card_run:443`): one at the first snapshot (nothing ran), one at the final snapshot after
the program had already matched (`scalar-fp.mic`, job `claude-1b96f540...`), and one earlier.
Each time a `gpt61` job was starting or ending on the card. The likely cause: a `PROC` line that
does not split into 6 tab fields, from a process that ends while `snapshot` reads it, or a field
holding a tab or newline. The error does not show the line, so this is not confirmed.

Acceptance (T0, fake transport with card-sized `/proc`):

- [ ] Red first: the refusal message shows the offending line, escaped and cut to 200 bytes
- [ ] A process whose `/proc` entry disappears between reads is skipped, not refused, and so is a
  line that has the `PROC` tag but is cut short because the process ended. A line that parses
  and is not ours stays listed, and one that names our run dir but cannot be read still refuses
  (fail closed for our own processes only)
- [ ] `exe`, `cwd` and `comm` values are printed so that a tab or newline in them cannot split a
  record (for example `od`-free escaping in the remote script)
- [ ] The final snapshot after a finished program never turns a matched program result into an
  infrastructure failure for a foreign process's race; the result keeps the program's class and
  notes the skipped process
- [ ] Two `--file` gaps from S2-14, found by the lead's torture run on 2026-11-03 (job with 257
  staged files): (a) every staged program arrived non-executable (`exec: Permission denied` for
  all 256), because the host's execute bit is meaningless under Windows Python; mark a staged
  file 0700 when it starts with the ELF magic `ELF`, else 0600, red first; (b) staging has one
  deadline of `transportTimeout` (10 s) for all files, so 257 uploads ran out after six
  (`SSH upload deadline`); give each file its own `transportTimeout`, or scale the deadline with
  the file count, red first
- [ ] The card tests pass under Cygwin, as `pm.py approve` checks; no card access
