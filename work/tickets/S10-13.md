Owner's request (2026-11-12): "Make sure our implementation avoid cbrtl or fall back to scalar if encountered,
and warn user for this behavior if their code is found using it during compiling."

Found by S10-12: the card's MPSS libm `cbrtl` (long double cube root) faults for many finite arguments.
`s_cbrtl.S:178` (`cbrtl+0xea`, `fldt (%rdx,%rcx,1)`) zero-extends a negative table offset through `ecx` and
reads about 4 GiB past its table; the first fault seen was `cbrtl(1e-5)` (card 2026-11-12 08:55Z, outputs in
`.work/_shared/tmp/claude-next16/s1012-cbrt*.out`). S10-12's model of the condition: the frexp exponent of
|x| has a negative remainder mod 3 (`tests/vmath/cbrt_screen.c`); confirm or correct this on the card.
Its harness fix keeps the argument in [1,8) and rescales exactly (`screen_cbrt` in `tests/vmath/qualify_v1.c`).

Lead audit (2026-11-12): none of the 24 installed KNC target libraries in `.work/_shared/gcc-knc-16.2.0`
(libgcc, libgcc_s, libgfortran, libstdc++, libgomp, libatomic, libknc_vmath, ...) references `cbrtl`; in
this repo only `tests/vmath/qualify_v1.c` calls it. So the exposure is user code: direct `cbrtl` calls,
`__builtin_cbrtl`, `std::cbrt(long double)`, and the type-generic `cbrt` on a long double.

As a user: under `-march=knc`, code that calls `cbrtl` does not crash. It gets a correct result from a safe
scalar replacement, and the compiler warns once per call site that MPSS libm's `cbrtl` is unsafe on the card
and a replacement is used. `-Wno-<name>` silences it. x86 is unaffected.

Deliver:
- A safe scalar `cbrtl` for k1om in the runtime that is always linked under `-march=knc`, for example
  `__knc_cbrtl` in libgcc (no libm dependency) or in a library on the default link line. Write it yourself
  (clean room, ADR-0013): exact power-of-two scaling into a range where the core is safe, then a long double
  core that does not touch MPSS's table path. Specials as C Annex F (+-0, +-inf, NaN, subnormals, negative x).
  Accuracy no worse than 1 ULP of long double against MPFR; say the measured bound.
- The compiler, under `-march=knc` only: calls to `cbrtl` (the builtin, and a declaration matching it) go to
  the replacement, and each such call site gets a warning under a new option, on by default for KNC
  (ADR-0006 hook rules, KNC branch, smallest shared footprint). Cover `cbrtl(x)`, `__builtin_cbrtl(x)` and
  `std::cbrt(long double)`. State plainly what is not caught (`-fno-builtin` without a matching declaration,
  function pointers, objects compiled earlier, `dlsym`) and document it on the flags page with the advice.
- Point `screen_cbrt` in `qualify_v1.c` at the same rule or leave it; say which.
- Extend the audit into a check: a script (or a step in an existing check) that runs `nm` over the installed
  KNC target libraries and fails if any references `cbrtl` other than the replacement.

Acceptance:

- [ ] Red first: a T1 test that `cbrtl`, `__builtin_cbrtl` and `std::cbrt(long double)` at `-O0` and `-O2
  -march=knc` call the replacement and warn, that `-Wno-...` silences the warning, and that x86 calls `cbrtl`
  with no warning
- [ ] Host model of the replacement against MPFR: every exponent residue across the long double range,
  subnormals, both signs, specials; the measured worst ULP stated
- [ ] A native program for the lead, multithreaded over every CPU it is given (AGENTS.md), that calls the
  replacement over the same set plus 2^24 random long doubles on the card and compares bit for bit with the
  host's results for the same inputs (both are x87 80-bit); and one direct call of MPSS `cbrtl` on a known
  faulting input that is expected to fault, run as a separate staged command, to confirm the cause. Staged
  with the exact `card_run` commands
- [ ] The library audit check passes; T0/T1/T2 otherwise unchanged; shared lines reported; x86 check by the lead
