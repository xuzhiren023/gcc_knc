Ticket P of `docs/research/knc-div-sqrt.md` section 5.1, item 3. The FP32 proofs rely on the
manual's error bounds for `vrcp23ps` (0.912 ulp) and `vrsqrt23ps` (0.775 ulp). These probes measure
the hardware against them, so the proofs no longer depend on the manual's wording.

Deliver one C program, `tests/regress/knc-estimate-probe.c`, in the style of
`tests/regress/knc-unaligned-probe.c`. Use inline asm, build at `-O0` with the KNC GCC 16, and
put the build command in its header. It covers:
- P1a: `vrcp23ps` over all 2^23 significands in [1,2). Print the maximum error in ulps against an
  exact reference, and `check=ok` or `FAIL` against 0.912.
- P1b: `vrsqrt23ps` over all 2^24 values in [1/2,2). The same, against 0.775.
- P1c: `vgetmantps`/`vgetmantpd` on subnormal inputs with DAZ=0.
- P1d: a masked-off lane raises no flag. A `vrcp23ps` of 0 in a masked-off lane must leave
  divide-by-zero clear.
- P1e: `vrcp23ps` of `0x3FFFFFFF` (shows whether S5-03's step 15 matters on this part).

Use exact integer or rational arithmetic for the references, not x87 division. Print one line per
item, with no per-input output. The lead runs it on the card (`tools/card_run`, under 64 MiB).

- [ ] The program compiles with the command in its header and passes `tools/knc_lint` (host only)
- [ ] A host self-check of the reference arithmetic, described in its header, passes
