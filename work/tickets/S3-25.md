S3-23's trunk run found it (`docs/research/m1-result.md`, criterion 5;
`.work/_state/logs/S3_23_trunk_t1_t2-20261104-093427.log`). All 16 `t1 packed ABI ... VAR_GET`
rows fail on trunk with an ICE at `tree-stdarg.cc:1072` (`gcc_assert (gsi_end_p (i))` in
`expand_ifn_va_arg_1`). The bug is ours and is in 16.2 too. The KNC guard at the top of
`ix86_gimplify_va_arg` (`i386.cc`, `if (TARGET_KNC && !ix86_knc_check_abi_type (...)) return
error_mark_node;`) reports its error and then returns `error_mark_node`. The expansion left behind
is not well formed. 16.2 is built with `CHECKING_P=0`, so it turns the ICE after an earlier error
into "confused by earlier errors, bailing out", and our check counts that as a clean rejection.

Fix: after the diagnostic, return a well-formed value of `type` so the expansion stays valid, for
example a zero constant of the type, or a fresh temporary for an aggregate. Read how other targets
leave an error path in their `gimplify_va_arg_expr`, and say which pattern you followed. The body
belongs in `i386-knc.cc` behind the existing one-line guard (ADR-0006 rule 1). Shared lines and
hunks must not go up.
