Sprint 11 goal 3 (`docs/sprints/SPRINT-11.md`): Sprint 12 profiles the corpus and Sprint 13 decides Milestone M4 on it
(median whole-program speedup over GCC 5.1.1 of at least 1.25x, no program more than 5% slower without a known
cause, `docs/PROJECT_PLAN.md` section 6). Today the corpus was only compile-surveyed (S0-07,
`docs/research/corpus-and-coverage.md`); nothing runs it.

The corpus (read-only packages in `.work/_shared/corpus/`, `SOURCES.txt`; licences in the S0-07 doc): PolyBench/C
4.2.1, STREAM 5.10, NPB 3.4.2 (CG, EP, MG Fortran/OpenMP; IS C/OpenMP), HPCG 3.1 (C++/OpenMP), zlib 1.3.1, SQLite
3.46.1, bzip2 1.0.8. **Held out, by program:** PolyBench adi and durbin, and all of bzip2. Their builds and runs are
allowed, but nothing about them (diagnostics, profiles, timings) may guide any tuning decision; the harness marks
their results `held_out` and the summary keeps them apart.

Compilers: GCC 5.1.1 is the donor, `.work/_shared/toolchain/cross/bin/k1om-mpss-linux-gcc` (and `-g++`, gfortran
where present) with its own runtimes; GCC-KNC is the installed prefix `.work/_shared/gcc-knc-16.2.0` (`-march=knc`).
Both build with `-O2` as the baseline pair; the harness takes extra flag sets per compiler (for example `-O3`,
`-mphinix`) so later tickets compare without editing it.

Deliver:
- `tools/corpus.py` (or `harness/corpus/`): extract the packages into `.work/_shared/corpus-build/`, build each
  program with each compiler and flag set, stage the binaries and inputs, run them on the card through `card_run`
  (the lead runs card jobs; the tool prints the exact commands or a single lead script), and collect results.
- **Frozen inputs and checks**, chosen once and recorded in the tool: PolyBench at a dataset size that runs 1-10 s
  on the card (deterministic init, checksum of the output arrays compared between the two compilers within a
  stated FP tolerance); STREAM with arrays several times the cache; NPB at the class that fits card memory, using
  NPB's own verification; HPCG's reference problem and its validity report; zlib and bzip2 compressing and
  decompressing a fixed generated corpus, round trip checked byte for byte; SQLite running a fixed SQL script with
  a checked result. Generated inputs come from a fixed seed in the tool, not downloaded.
- **Threads:** OpenMP programs at 240 threads and at the best density the S11 bandwidth work found (1 per core),
  recorded per run; serial programs pinned to one core. Every program multithreaded over every CPU it is given
  where its algorithm allows (AGENTS.md).
- **Results:** one JSON line per (program, compiler, flags, run) with time, check result, threads, input; a summary
  table of per-program speedup GCC-KNC over GCC 5.1.1 with median, held-out separate; failures listed, never
  dropped. Paired, interleaved launches per program (ADR-0010) with at least 3 repetitions.
- A host test of the harness logic (plan, result parsing, summary maths, held-out separation) on fake results.

Rules: no card job by the engineer; no GCC build (ask the lead if GCC must change; a corpus program that GCC-KNC
cannot build is a finding for a ticket, recorded, not worked around in the corpus source); corpus sources are
never edited (build flags and harness files only). If `pm.py commit` fails, leave changes uncommitted and
`pm.py ask`; the lead commits (owner 2026-11-12).
