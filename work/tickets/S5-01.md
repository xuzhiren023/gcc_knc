Facts already settled (do not re-derive):
- ADR-0005: the packed modes are V16SF, V8DF, V16SI and V8DI only. KNC never sets `TARGET_AVX512F`.
- ADR-0007 and `docs/research/knc-masks.md`: masks are HImode for 16 lanes and QImode for 8.
  For QI masks, bits 15:8 are undefined after `kmov`, so 8-lane emptiness is a byte test, never
  `jkzd` or `kortest`.
- S3-03 (`docs/research/knc-unaligned-probe.md`): masks never suppress a fault on loads and
  stores. Unaligned pairs need element alignment.
- `imci.md` is read before `sse.md`, so it may not use names that `sse.md` defines. Shared i386
  changes take ADR-0006 forms: hooks, mode-tested condition terms, entry dispatch.
- `vgminps` and `vgmaxps` treat signed zeros differently from C `fmin` and `fmax`, so S4-03 kept
  those scalar.

Answer:

1. **Gather and scatter forms.**
   - The forms: `vgatherdps`, `vgatherdpd`, `vpgatherdd`, `vpgatherdq`, the scatter forms, and
     the gather/scatter prefetch hints.
   - For each: index width (are indices 32-bit for 8-lane types?), scale, element order, and the
     duplicate-index rules for scatter.
   - The partial-completion contract: the mask is cleared per element completed, and the
     instruction may stop early, so it runs in a `jknzd` loop.
   - The fault footprint: does a masked-off element ever touch memory? Does a fault on element k
     leave the earlier elements done and their mask bits clear?
   - Say what the manual states and what it does not. Write a card probe for whatever is unstated
     or matters for correctness (item 6).
2. **GCC 16 entry points for indexed access.**
   - Which interface i386 uses for AVX2 and AVX-512 today: the `gather_load`, `mask_gather_load`,
     `scatter_store` and `mask_scatter_store` optabs, or `TARGET_VECTORIZE_BUILTIN_GATHER` and
     `_SCATTER`.
   - How the vectorizer picks between them (`tree-vect-data-refs.cc`,
     `vect_check_gather_scatter`, `tree-vect-stmts.cc`).
   - What KNC must provide so that, for each packed mode, these vectorize: `a[i] = b[idx[i]]`,
     `a[idx[i]] = b[i]`, and the conditional form `if (m[i]) a[i] = b[idx[i]]`.
   - The offset type rules, for example a signed 32-bit index for an 8-lane double gather.
   - Whether the existing AVX-512 code can be reached behind ADR-0006 forms, or KNC needs its own
     `imci.md` patterns.
3. **Permutes.**
   - The IMCI forms: swizzles on register operands (`{cdab}`, `{badc}`, `{dacb}`, `{aaaa}` and so
     on), `vpermd`, `vpermf32x4`, `valignd` and `vpshufd`.
   - Which GCC 16 hook covers each: `TARGET_VECTORIZE_VEC_PERM_CONST`, `vec_perm<mode>`,
     `vec_shr`, `vec_extract`, `vec_init`, `vec_interleave*` and `vec_reverse`.
   - What the vectorizer needs for reversed loops (`a[n-1-i]`), interleaved complex data (stride 2)
     and even/odd extraction, and the cheapest IMCI sequence for each.
   - Which i386 `ix86_expand_vec_perm_const_1` paths would wrongly fire for KNC modes today.
4. **Reductions.**
   - The optabs: `reduc_plus_scal_<mode>`, `reduc_smax`, `reduc_smin`, `reduc_umax` and
     `reduc_umin_scal`, and `reduc_and`, `reduc_ior` and `reduc_xor_scal`.
   - The vectorizer's epilogue fallbacks: `vec_shr` or whole-vector shifts, and `vec_extract` of
     halves.
   - The cheapest IMCI tree for 16 and 8 lanes: a swizzle plus `vpermf32x4`, or `vpermd`.
   - FP ordering: GCC reassociates an FP sum only under `-fassociative-math`. Otherwise it uses an
     in-order `fold_left_plus` or stays scalar. State what GCC 16 does for `float s += a[i]` at
     `-O2 -ftree-vectorize` and at `-O3` without fast-math.
   - Recommend the contract (ADR-0003 point 2: no implicit fast-math).
5. **FP min/max.**
   - Compare C `MIN_EXPR`/`MAX_EXPR` and `fmin`/`fmax` with `vgminps`, `vgmaxps` and
     `vgmaxabsps`: NaN operand order and signed-zero results, with manual pages.
   - Which C forms can map exactly, if any (for example `a < b ? a : b` with
     `-ffinite-math-only`), and which reductions follow from that.
6. **Probe.**
   - Cover every correctness fact the manual leaves open: the gather/scatter fault footprint for
     masked-off lanes, partial completion after a fault, scatter with duplicate indices, and
     `vgmaxps` on mixed zeros and NaN.
   - Write one C probe, `tests/regress/knc-gather-probe.c`, in the style of
     `tests/regress/knc-unaligned-probe.c` (guard pages, `sigsetjmp`).
   - Build it with the KNC GCC 16 at `-O0`, using inline asm for the instructions, and give the
     build command in its header. The lead runs it on the card.
7. **Recommendation and estimate.** For each of E4-02 and E4-06, give:
   - the patterns needed in `imci.md`;
   - the shared hunks needed, with estimated lines and the ADR-0006 form for each;
   - the risks;
   - a proposed split into gcc tickets, with the T1 scans and native checks that would prove each.
