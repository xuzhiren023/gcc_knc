On 2026-11-03 two card jobs in a row were refused with `unknown process identity in snapshot:
b'PROC\t242373\t\tkworker/u:7\t\t'`, both while a `gpt61` job was running. Minutes earlier, jobs had
passed. The record has an empty parent pid, and no `exe` or `cwd`.

Cause, from reading `tools/card_run_remote.sh:77-121`: the snapshot reads `/proc/<pid>/status` twice.

1. The shell loop reads it for `PPid:` (lines 80-83) and drops kernel threads by parent 2. When
   that read fails or misses the line, `proc_ppid` is empty, the process is not dropped, and
   `IDENT pid <empty>` is printed.
2. The awk `END` block (lines 116-119) reads `status` again, only to test that it is readable, and
   then tags the record `PROC`.

So a kernel thread whose first read failed comes out as a complete-looking `PROC` with an empty
parent. `tools/card_run:493-501` then refuses the whole job.

Fix: in the awk `END` block, read `PPid:` from the `status` read it already makes. Use that value as
the record's parent; drop the record when the parent is 2 (or the pid is 2); tag it `SKIP` when
`PPid:` cannot be read. Remove the shell loop's parent filter only if the awk read fully replaces
it. Keep the identity rules: never trust names.
