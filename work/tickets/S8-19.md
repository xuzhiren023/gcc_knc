Fix for S8-08, found on the card 2026-11-10. GCC 16's `pass_align_tight_loops`
(`i386-features.cc`, tune flag `X86_TUNE_ALIGN_TIGHT_LOOPS`, on for every tuning but Zhaoxin,
Skylake-AVX512, Cascade Lake and Core Atom) puts `.p2align ceil_log2(size)` with no max-skip before
every loop no larger than `prefetch_block` (64 for KNC). It exists for the decoded-icache rules of big
cores, which KNC does not have. When such a loop is entered by fallthrough, as 2.22 fills the gap with
one-byte `nop`s that run on every outer trip.

Measured: in m2_mat8 the inner loop `.L101` gets `.p2align 6`. knc runs 40 nops per outer trip,
S8-08's function alignment moves that to 56, and mat8 is 1.105x slower at L2 d4 on both launches
(card 2026-11-10 05:14Z, `.work/_shared/tmp/claude-s8-14-out/s08-mat8-L2-*.out`). The earlier A/A
placement swings (mat8 1.34x at 16, 0.76x at 32) fit the same cause, since shifting the code
changes the nop count.

Deliver, in `i386-knc.cc` `ix86_knc_tune_features` next to `X86_TUNE_FAST_PREFIX`: clear
`X86_TUNE_ALIGN_TIGHT_LOOPS` for `-mtune=knc` (a user `-mtune-ctrl=align_tight_loops` still wins, the
same order as FAST_PREFIX). Add the flag with its reason to S8-08's table in
`docs/research/knc-costs.md`. Keep S8-08's 64-byte function default.
