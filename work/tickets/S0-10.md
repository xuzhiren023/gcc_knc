Since S0-08, the compiler's default sysroot is the card-derived one, and it has the runtime
libraries but not glibc's development links. The lead checked on 2026-11-02: a C hello links,
but `k1om-mpss-linux-gfortran hello.f90` fails with `ld: cannot find -lm`, so every Fortran
program fails, and so does any C program using `-lm`, `-lpthread`, `-ldl` or `-lrt`. S0-08
tested only a plain C link. Before S0-08, the PhiWeather sysroot supplied these links.

`sysroot/lib64` already has every runtime file needed: `libm.so.6`, `libpthread.so.0`,
`libdl.so.2`, `librt.so.1`, `libcrypt.so.1`, `libutil.so.1`, `libresolv.so.2`, `libnsl.so.1`,
`libanl.so.1`, `libthread_db.so.1`. The lead seeded the four files that cannot be made from
them into `.work/_shared/toolchain/sysroot-development/`: `libpthread_nonshared.a`, `Scrt1.o`,
`gcrt1.o`, `Mcrt1.o`. Do not read PhiWeather.

Acceptance:

- [ ] The `sysroot` step of `tools/toolchain.py` also installs the four seeded files, and creates
  `usr/lib64/lib{m,dl,rt,crypt,util,resolv,nsl,anl,thread_db}.so`, each resolving to the matching
  `/lib64` runtime file, and `usr/lib64/libpthread.so` as glibc's linker script:
  `GROUP ( /lib64/libpthread.so.0 /usr/lib64/libpthread_nonshared.a )`. Plain files or linker
  scripts are fine; Cygwin symlinks are not, because native Windows tools cannot read them
- [ ] With default flags, `k1om-mpss-linux-gfortran` links a Fortran hello, and `k1om-mpss-linux-gcc`
  links a C program using `-lm -lpthread -ldl -lrt`, with no PhiWeather path in `-v -Wl,--trace`
- [ ] The `verify` step and `tools/doctor` cover this, and doctor names the `sysroot` step when a
  link is missing. A T0 test shows the check fails when one is missing
- [ ] `tools/check t0 t1 t2` still matches `tests/baseline/donor-gcc5.txt`
