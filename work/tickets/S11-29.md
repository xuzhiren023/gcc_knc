Owner 2026-11-13: profile runs must not ask the 3100- and 5100-series cards for what their hardware cannot do, and
must not fail where the hardware would succeed. S11-28's card round (2026-11-13 15:10 EST,
`.work/_shared/S11-28/memory-results.json`, log `.work/_state/logs/S11_28_memory-20261113-145740.log`) shows that
today's profiles do fail where the hardware would succeed.

- `--profile 3100`/`5100` enforce the card's usable memory (5632/7680 MiB, `PROFILE_MEMORY_MIB`) as `RLIMIT_AS`.
  That limit counts reserved address space, not memory in use.
- OpenMP HPCG 104³ under 3100/5100 at 2 and 4 threads per core aborts with `std::bad_alloc`. Peak *resident* memory
  (`VmHWM`) is only 0.51-0.92 GB, against `VmPeak` 1.5-6.3 GB of reservations.
- With `MALLOC_ARENA_MAX=2` the same 224-thread run survives (VmPeak 2.8 GB, VmHWM 0.9 GB): glibc's per-thread malloc
  arenas, 64 MiB of reservation each, are what exhaust the limit.
- A real 3120 has 6 GB of RAM, overcommits address space, and would run this program in under 1 GB.

Deliver:
- Profile memory becomes a limit on memory in use by the job's process tree: resident set plus swap if any,
  covering every process the job starts. Exceeding it fails the job with result class `resource` and a reason naming
  the peak and the limit. No address-space limit in profile runs.
  - Choose and justify the mechanism. Use a cgroup memory limit if the MPSS kernel provides one without any MPSS,
    module or `/etc` change. Otherwise a card-side monitor samples the tree's `VmRSS` (`/proc/<pid>/status`, children
    included) at least every 100 ms and kills the tree on exceeding the limit.
  - State the monitor's detection limit: a fast spike between samples can pass. Keep its overhead negligible: one
    reader process, no busy loop, measured.
- The receipt records the profile's limit and the job's peak resident memory, for every profile run.
- `full` and the exclusive no-limit rule (S9-23) are unchanged. The admission check on MemFree and the margin is
  unchanged. Every other card_run guard is kept, as in S11-02.
- Do not change the program's environment (no `MALLOC_ARENA_MAX`, no stack settings): the program must behave as on
  the real card.
- Stage one lead card round under `.work/_shared/S11-29/`:
  - OpenMP HPCG 104³ (S11-28's build) under 3100 at 224 threads and 5100 at 236 threads must run, with peak resident
    memory in the receipt.
  - A small allocator that touches 6 GiB under `--profile 3100` must fail as `resource`.
  - The same allocator touching 1 GiB must pass.
  - Bounded to about 10 minutes.
- No GCC build. No card job by the engineer. If `pm.py commit` fails, leave changes uncommitted and `pm.py ask`.
