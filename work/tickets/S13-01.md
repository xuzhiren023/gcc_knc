Draft until S12-09 is approved; the lead records the frozen final GCC-KNC prefix revision then.

Stage the complete ADR-0015 gate for the lead, exactly as frozen (docs/adr/0015-m4-scoring-and-measurement.md;
docs/M4-DEFINITION.md pass rule): all 17 programs including the three held-out programs (unsealed only now, by the
documented procedure), GCC 5.1.1 vs GCC-KNC serial -O2 (SQLite donor exception disclosed), six paired launches per
program per model in the order AB, BA, AB, BA, AB, BA, on full 7120, `--profile 3100` and `--profile 5100`. Write
the README with the expected card time per profile (it must fit one exclusive window; split by profile if not) and
the one predeclared six-pair extension as a separate script that the lead runs only if the protocol calls for it.

Also stage the labelled panels as separate, later scripts: -O3, -mphinix, PGO (training separate from evaluation),
GCC-KNC OpenMP at 240 threads (60/120 side panels). They never change the primary decision.

The scorer (tools/corpus or the S11-14 protocol tool) computes, from the raw records only: per-program median paired
speedup, the 17-program median, its one-sided 95% lower bound by the frozen bootstrap (10,000 replicates,
`random.Random(1514)`), correctness for every launch, and every confirmed slowdown above 5%. The lead runs the card
jobs and writes the decision. No threshold, denominator or program set changes after results.
