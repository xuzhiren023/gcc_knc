Backlog E4-04, part A (split on 2026-11-04 to speed up Sprint 4; part B, misaligned masked access,
is S4-14). Design: ADR-0007 point 7 (`docs/research/knc-masks.md` section 5). The lead's
implementation plan is in `docs/research/s4-05-plan.md`, part A. Read it first.

Deliver: `while_ult` in `imci.md` (mask computed in a GPR, then `kmov`; HI for 16 lanes, QI for 8);
the KNC term in `ix86_vector_costs::finish_cost` that asks for a masked epilogue only when every data
reference is known 64-byte aligned with no peel (one line, mode-tested, ADR-0006 rule 1); and the
`cond_<op>` optabs a masked FP epilogue needs beyond S4-03's `cond_add`/`cond_sub` (at least
`cond_mul` and `cond_fma` for `y = a*x + b`). `param_vect_partial_vector_usage` stays 0.

Lead decisions on the plan (2026-11-04):
- Masked epilogues apply only to loops aligned with no peel (global arrays, `aligned(64)`,
  `__builtin_assume_aligned`). After an alignment peel, GCC marks epilogue accesses as unknown
  alignment (PR 92351, plan item 2), so peeled loops keep the x87 remainder. S4-14 decides about
  S4-03's cost term.
- `cond_fma` is required, not deferred, so an FMA body and its masked epilogue round the same way
  (S3-10's inexact check compares them).
- 8-lane (QI) masks are tested with a byte test, never `jkzd` (`kmov r32,k` copies bits 15:8).
- Part A cannot be tested at `-fvect-cost-model=unlimited` (the target's epilogue suggestion is
  ignored there); test it at `-O2 -ftree-vectorize` and `-O3`.

S4-03's
aligned `maskload`/`maskstore` are the only masked memory accesses: a masked access is issued only
with a non-empty mask on a 64-byte aligned line (S3-03).
