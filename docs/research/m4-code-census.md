# M4 development code census

Static snapshot of S11-18 primary executables, generated by `tools/code_census.py`.
Static counts are not time. S11-15 profiles must supply execution frequency and removable wall-time weighting; this census selects no theme.

## Scope and interpretation

Only the 14 allowlisted development programs are disassembled, once per compiler. The metadata held-out flag is filtered before file access; names and input path components are also guarded. No corpus source, shared library, held-out executable, card job or compiler build is accessed. All executable sections from `objdump -d` are included: startup, PLT and statically linked helpers can contribute. Different linked helpers and inlining prevent treating whole-executable differences as isolated backend effects.

Primary requested flags are `-O2`. Actual flags and variants are recorded below; the SQLite D build is `-O3` and uses its staged assembly fallback, so its comparison is not an equal-optimization-level backend experiment.

Counts are sites. Bytes sum decoded instruction bytes (including wrapped byte lines), not ELF file size. Vector means an explicit zmm/ymm operand; mask-only instructions are separate. Scalar includes integer, x87, control, padding and setup. Vector share is instruction share, not lane utilization or FP work.

Stack loads/stores via rsp/rbp are proxies, not proven spills: frame locals, arguments, callee saves and frame-pointer-free rbp data can contribute. GPR/x87/zmm/k classes follow explicit operands/mnemonics. Push/pop callee saves are counted separately; mov-based stack saves/restores are candidates and overlap stack counts. x87 memory counts fld/fst families; fxch is separate. Transfer candidates are store then load to the same textual address within 64 instruction bytes, across x87/zmm classes, cleared at calls/control flow/stack-base changes. Aliasing, widths, base-register changes and dataflow are not proved; these are inspection leads, not confirmed transfers.

Loop regions are address intervals ending in a backward direct branch to an instruction in the same function. They are CFG layout proxies, not dominator-proven natural loops; cold paths, nested loops and unstructured flow can distort them. Per-loop JSON counts may overlap; loop totals use the union of intervals. No opt-info is required. Address proxies count lea, imul and sign extensions; imul may be data arithmetic rather than index work. Loads/stores use explicit AT&T parenthesized operands and read-modify-write heuristics; implicit string/stack traffic, absolute addresses and exact vector memory semantics are not fully represented.

Backward/forward branch counts expose layout direction only. Taken frequency, prediction hints, branch probabilities, alias blocking, reuse distance, cache misses and profitable scalar FP conversion cannot be recovered from these binaries.

## Observed patterns

Scalar overhead: GCC-KNC has more decoded instruction bytes in 14 of 14 programs. Loop address sites differ in both directions: SQLite 11372 / 9387, HPCG 2056 / 2372, zlib 483 / 484 (D / K). Inlining, vector setup, tails, helper coverage and the SQLite flag exception all complicate causality.

Pressure: stack traffic spans dense, sparse and control-heavy styles. PB-ludcmp has 4 / 130 x87 stack-load sites; HPCG has 1811 / 2555 and SQLite 17224 / 22452 GPR stack-load sites (whole executable, D / K). These are pressure/local-storage leads, not verified allocator spills.

Reuse: loop loads/stores are 276 / 259 / 139 / 119 in STREAM and 49 / 147 / 18 / 102 in PB-gemm (each pair D / K). Static memory-site differences cannot distinguish duplicated paths, new vector setup, redundant accesses and necessary work.

Vectorization: zlib has 0 / 0 explicit vector sites, while PB-gemm has 10 / 311 and NPB-MG 15 / 1172 (whole executable, D / K). Dense and stencil code show vector expansion; branch-heavy integer code remains scalar by this measure. None of these counts identifies aliasing as the cause.

Prefetch/store choice: loop prefetch sites are 0 / 18 in STREAM, 0 / 106 in NPB-CG and 0 / 608 in SQLite (D / K), reaching streaming, sparse and database styles. STREAM has 0 / 14 non-temporal/NGO mnemonic sites. Extra sites are neither proof of useful coverage nor waste.

Scalar FP: x87 sites remain in dependence-heavy science (PB-cholesky 57 / 107, PB-ludcmp 71 / 319), random/math work (NPB-EP 247 / 286), and database code (SQLite 1440 / 1427); zlib has 0 / 0 (whole executable, D / K). This locates FP styles for profile correlation without implying that strict scalar-to-VPU conversion is legal or profitable.
