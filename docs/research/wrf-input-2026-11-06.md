# Input from the WRF KNC tuning work (2026-11-06)

Source: `C:\Users\xuzhi\Documents\card-coordination\wrf-hot-loops-for-gcc-knc.md`, written by the
PhiWeather WRF tuning session on the lead's request (owner-approved). Its claims are tagged
measured / observed / belief there; figures below keep those tags. **Input, not requirements**

x87 scalar, `-fno-tree-vectorize`; their gains come from generated IMCI kernels called from Fortran.

## What it tells us

| Finding (their tag) | GCC-KNC consequence | Where |
|---|---|---|
| Hot rows are short: `i` innermost, 7-9 cells of 16 lanes (mean 46% lane use), `k` 50-51, j/k/i order, ~29 arrays per point (observed) | M2 kernels need a short-row strided kernel; masked single-pass tails matter more than long-loop throughput | E5-06, E4-04, S6-05/06 |
| Short rows are latency-bound: 8 GB/s at 120 threads without prefetch, 19.5 with `vprefetch0` two rows ahead (2.4x); long streams reach 87-146 GB/s (measured) | Prefetch is the biggest single lever for scalar and vector short-row loops; GCC 5 emits none | E5-07, E7-06 |
| Constant divisors (`/12`, `/60`) are exact in 3 instructions: `q=RN(a*r); e=fma(-c,q,a); q'=fma(e,r,q)`, checked on 76.7 M patterns (measured) | Vectorizable division by a constant without giving up correct rounding (ADR-0003); x87 `fdiv` cost ~69 cycles per point in their fit | E4-03 |
| Gathers need the `vgatherdps`/`kortest`/`jnz` retry loop; single-shot gave NaNs (measured) | Already GCC-KNC's lowering (E4-02); confirms the test design | E4-02 |
| Unaligned access needs `vloadunpackld/hd` pairs, high half only when the span crosses a line; unconditional high half faulted on a guard page (measured) | Matches E3-01's probe and our moves; keep the fault case in tests | E3-01, E3-03 |
| glibc's word-copy `memcpy` runs 0.57 GB/s on one thread; a 16-lane prefetching copy was 1.6-3.4x and -2.5% WRF wall (measured) | Inline block-move expansion with IMCI for known sizes is a compiler item; the library `memcpy` is libc's (PhiNix track E) | new E5-10 |
| Libm `powf`, `pow`, `expf`, `logf` are 2.5-4.7% of samples (measured) | Vector math is real but second-order; their qualified 16-lane `expf`/`logf`/`powf` exports use `_ZGVeN16v` names, which E7-01 says not to reuse | E7-01, E7-02 |
| 2 threads per core was best for WRF; 3/core +17-45%, 4/core slower (measured, their workload) | ADR-0009's default of 4 threads per core is a kernel-throughput default; report results at 2 as well, and do not claim 4 is best for whole programs | ADR-0009 review, E5-06 |
| ~9,850 OpenMP regions per rank per step, fork ~17 us, barrier wait 54-58% of thread time (measured) | libgomp fork/join and barrier cost on KNC is worth measuring in E6-03 | E6-03 |
| Loop-invariant `sin()` and `SIZE()` left inside loops by GCC 5 at -O2 (observed) | gfortran defaults to `-fno-math-errno`, so GCC 16 should hoist these; check in the corpus | E7-03 |
| VPU flushes denormals, x87 does not; FMA contraction changes rounding vs the x87 baseline (observed) | The FP policy for vector code (FTZ/DAZ, contraction) must be explicit and documented | ADR-0003, E5-09 flags page |
| GCC 5 k1om emitted `vpackstorelps` through an uninitialized callee-saved base register at -O1/-O2 (measured) | A donor defect; worth a regression test that GCC-KNC is clean | E2-02 tests |
| I/O: rank-0 netCDF writes 10-15% of wall, fixed-cost dominated (measured) | Not a compiler item | none |
