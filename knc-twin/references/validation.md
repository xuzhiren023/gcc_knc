# Validation: held-out kernels, ranking reliability, validated shapes, open misses

Full tables: `tests/heldout_native/characterization-run/validation.md` and `validation.json`
(regenerated by `scripts/validate_heldout.py`; the measured rows are copied in
`tests/heldout_native/measured-characterization.json` from gcc_knc's
`docs/research/knc-characterization.md`). Everything predicted below is a model output; the
measured columns are native TSC ticks per unit per thread on the project's 7120-class card.

## What was validated

The gcc_knc characterization catalog (`tests/bench/knc-char/kernels.py`, 364 assembly
microkernels; the 119 rows with native measurements are used) was run through the compiler-
output adapter unchanged (prologue, 32-unit loop, epilogue) and simulated at 1, 2 and 4
contexts with the driver's memory layout (pointer chains for the latency kinds, direction bits
for C10). The prediction is the slope of completion cycles between two round counts, divided by
32, so prologue and cold start cancel; footprints that fit a cache level with all active threads
are declared resident there because the driver measures a warm steady state. TSC ticks and core
cycles are treated as equal (0.5% apart on this card).

Rows whose measurement fixed a profile parameter or exposed a model rule are **calibration**
rows (`CALIBRATION_ROWS` in the harness); the other rows are **held out**: no parameter was
touched to fit them.

## Results (profile card-7120-measured, scenario A: TLB modeled, hardware prefetcher off)

| rows | n | median abs err % | worst abs err % (row) | within 15% | within 30% | mean signed err % |
|---|---:|---:|---|---:|---:|---:|
| held-out characterization, 1 thread | 62 | 0.9 | 834 (memory.store_normal, HWP off); next 78 (spill_reload.rt) | 56 | 58 | +13 |
| held-out characterization, 2 threads | 62 | 0.4 | 631 (memory.store_normal); next 116 (spill_reload.rt) | 57 | 58 | +10 |
| held-out characterization, 4 threads | 59 | 1.6 | 349 (memory.store_normal); next 161 (spill_reload.rt) | 57 | 57 | +7 |
| held-out compiled code (S12-31, S12-30), 1 thread | 11 | 17.2 | 32 (S12-31 gas_0/mis_44/inc_0) | 3 | 8 | -10 |
| calibration, 1 thread | 53 | 0.7 | 863 (memory.load_rt, HWP off) | 50 | 52 | +17 |

The mean signed error is dominated by two memory rows that the HWP-off scenario cannot
reproduce (below); the median held-out characterization error is about 1%. Compiled code is a
different matter: the eleven compiled-code rows (below) have a median error of 17%.

**Ranking reliability**: 310 of 323 measured pairwise orderings within the named groups
(measured difference above 3%) are reproduced at the right order, 0.960; without the S12-31
group (4 of 10) it is 306 of 313, 0.978. The seven characterization disagreements: masked_load.lat vs spill_reload.lat at 2 threads (12.17 vs 12.98 measured, both
12.00 modeled), unpack.rt vs spill_reload.rt at 4 threads (the over-charged independent
reload pairs), memory.store_normal vs memory.store_stream at every thread count under scenario A
(no hardware prefetcher: the normal stream is charged full misses; scenario B orders them
correctly), and vaddps.rt/vpermd.rt vs masked_load.rt at 2 threads (masked_load.rt 2.37 is a
flagged measurement).

Groups reproduced completely: the five AGI gaps, C9 register and memory unroll orders (u1 > u2
> u4), C7 accumulators (tie), the latency ladder (scalar 1 < vector 4 < long 6 < pd->dq 7 <
masked 12 < x87 div 38), load levels L1 < L2 < memory for latency and throughput, the pairing
rows (vector+scalar pairs, vector+vector does not), prefetch pairing, gathers (one line vs
sixteen, .lat vs .rt), the branch rows.

| finding | rows | change |

## Open misses (held out, not tuned)

| row | measured | predicted | suspected mechanism |
|---|---|---|---|
| spill_reload.rt (independent store/reload pairs) | 5.09 / 4.20 / 4.26 | 9.06 / 9.06 / 11.12 | the store-to-load wait is modeled as an issue blocker; hardware lets independent pairs overlap. Native request: aliasing vs non-aliasing pairs |
| c9.memory.u2 / u4 (unrolled store-load chains) | 8.56 / 8.30 (1 thr), 12.03 / 11.01 (2 thr) | 7.0 / 6.5, 10 / 9 | the same mechanism: unrolling recovers less in hardware than the model's full overlap |
| gather_scattered.lat / .rt (16 lines) | 184 / 275 / 509, 175 / 260 / 507 | 124 / 224 / 448 | per-line occupancy is 7 for one line but about 11 for scattered lines (`occupancy.gather_cycles_per_line` alternative 11); the ordering one-line < scattered is right |
| memory.load_rt, memory.store_normal (sequential streams) | 37 / 48 / 78, 38 / 49 / 80 | scenario A 358 (no prefetcher); scenario B (HWP modeled) 37.4 / 48.1 / 85.5 and 35.5 / 47.9 / 85.5 | without the hardware prefetcher every line is a demand miss; with the sub-model the one- and two-thread rows match and four threads are 10% high (memory service 20 cycles per line is a four-thread measurement that includes the prefetcher) |
| c10.branch.fixed at four threads | 17.02 | 12.38 | prefetch-buffer refill after taken branches (R02 ch.4) is not modeled; at one thread the row matches (6.19 vs 6.22) |
| gather_all.lat (dependent one-line gathers) | 15.10 / 18.27 / 29.17 | 19.0 / 19.0 / 28.0 | the index-dependent chain pays the data latency (15) plus the mask path; the measured chain overlaps part of it |
| unpack.lat at 2 and 4 threads | 16.79 / 24.40 | 14.0 / 17.1 | contention of the four unaligned halves per unit on the L1 port is under-modeled |

## Compiled code: S12-31 and S12-30 (held out, S13-06)

Cases in `tests/heldout_native/<case>/`; predictions recorded in each `prediction.json` by
`validate_heldout.py --cases ... --record`; measured seconds converted with `card.clock_hz`
1.238 GHz. Both are single core, one thread, cache-resident and fully supported by the adapter
and the engine, so they are inside the model; neither shape is a validated shape.

| case / variant | unit | measured | predicted | error | limiting (model) |
|---|---|---:|---:|---:|---|
| S12-31 gas_0, mis_44, inc_0 | core cycles per 27-product row | 488.9 / 489.2 / 489.0 | 331 | -32% | spacing, x87 dependency |
| S12-31 adj_0, mid_0 | same | 433.5 / 432.5 | 358 | -17% | spacing, x87 dependency |
| S12-31 mov_adj_0, mov_split_0 | same | 487.9 / 487.6 | 412 | -16% | spacing, x87 dependency |
| S12-30 donor-off | core cycles per csr_raw call (416 nonzeros) | 8356 | 9518 | +14% | miss stalls, spacing |
| S12-30 knc-switch-off / knc-switch-on | same | 8484 / 8481 | 9527 / 9535 | +12% | miss stalls, spacing |
| S12-30 knc-switch-off-two-nests | same | 8284 | 9941 | +20% | miss stalls, spacing |

S12-31 (window 5 of `.work/_shared/S12-31/native-mb.log`; window 3 agrees within 0.5%): the
model is 16-32% fast and orders the variants wrongly: on the card the two orders with `faddp`
before the compare (adj_0, mid_0) are 11% faster than the rest, and adding a dead `movl`
(mov_*) costs nothing; the model makes adj/mid 8% slower than gas_0 and mov_* another 15%
slower. Known defect (not fixed, timing-rule change pending a lead answer): x87 arithmetic with a memory
operand gets its result at the load latency, without the multiply/divide latency or divider occupancy.
Open (not tuned): the per-row cost of an x87 row loop with a memory-operand `fmull`,
`movslq` costed as a one-cycle V-pairable scalar op (no source), and front-end effects of the
instruction order. S12-30: 12-20% slow on a deterministic input (the card's columns are random);
the model ranks two-nests slowest where the card measured it fastest (2% apart, inside the
3% ranking threshold).

## A real candidate batch (`fixtures/batch`)

The S12-30 gate's CSR SpMV kernel (`csr_raw`: 32 rows of 13 nonzeros, x87 double) as emitted by
GCC-KNC in six policy variants and by the GCC 5.1.1 donor, on one deterministic integer-valued
input, ranked off-card with the frozen profile (`knc_twin.py batch fixtures/batch/manifest.json`):

| candidate | predicted cycles per call | ratio | measured seconds per call (gate, same case shape) |
|---|---:|---:|---:|
| donor-off | 9518 | 0.999 | 6.749e-6 (about 8315 ticks) |
| knc-switch-off (baseline) | 9527 | 1.000 | 6.853e-6 (about 8443 ticks) |
| knc-switch-on | 9535 | 1.001 | 6.850e-6 |
| knc-switch-on-contract-fast | 9535 | 1.001 | - |
| knc-handwritten-policy | 9939 | 1.043 | - |
| knc-switch-off-two-nests | 9941 | 1.044 | 6.690e-6 (about 8242 ticks) |
| knc-switch-on-min4 | 12255 | 1.286 | - |

The predicted absolute time is 13% above the measured call (unvalidated shape; the measured
input differs in its random columns). Three of the four measured variants are within 1% of each
other both measured and predicted; the model ranks the two-nests variant 4% slower where the
card measured it 2% faster. Every candidate lies within the manifest's 5% band of the baseline or
has unvalidated memory behaviour, so the batch sends all seven to the native queue
(`queue/<name>/request.json`) rather than claiming a ranking: this is the intended behaviour
for a batch the model cannot separate.

## Regenerating

```
cd tests/bench/knc-char && python -c "from pathlib import Path; import kernels; kernels.emit(Path(OUT))"
python scripts/validate_heldout.py --kernels-s OUT/kernels.s --kernels-h OUT/kernels.h \
    --measured tests/heldout_native/measured-characterization.json --out tests/heldout_native/characterization-run \
    --cases tests/heldout_native [--record]
python fixtures/batch/make_csr_batch.py --asm-dir <S12-30 .s directory> --out fixtures/batch
python scripts/knc_twin.py batch fixtures/batch/manifest.json --out <dir>
```
